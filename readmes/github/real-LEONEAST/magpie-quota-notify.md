<h1 align="center">Magpie 额度通知</h1>

<p align="center">额度不足、恢复、重置在即，及时推送到手机。</p>
<p align="center"><b>可视化设置 · 保存即生效 · 微信 / Telegram / MeoW / Bark / Webhook</b></p>
<p align="center"><a href="#安装">安装</a> · <a href="#页面预览">页面预览</a> · <a href="#提醒规则">提醒规则</a> · <a href="#致谢">致谢</a></p>

为 [Magpie](https://usemagpie.ai/) 提供额度监控与消息推送的 Bun 插件，适用于 Magpie 网页版，包括 Docker / NAS 部署。设置、状态和发送记录集中在一个页面，保存后直接应用，无需手动编辑 JSON。

插件仅查询额度接口，不发送模型提示词，不执行自动点灯或重置卡操作。

## 功能

| 功能 | 支持内容 |
| --- | --- |
| 额度提醒 | 最多三档剩余百分比、耗尽通知、恢复通知、重置前提醒 |
| 独立规则 | 5 小时和 7 天窗口分别选择提醒方式、提前时间 |
| 通知内容 | emoji 标注账号、套餐、额度、重置与读数时间；Plus 显示 5 小时和周额度，Pro 类套餐显示周额度 |
| 推送渠道 | MeoW、Bark、PushPlus、Server酱、Telegram、通用 JSON Webhook，可同时配置多个渠道 |
| 全局通知规则 | 统一选择接收事件和账号，所有启用渠道共享；保留单渠道测试 |
| 同轮合并 | 同一次额度检查的提醒合并为一条，按账号展示，分发到所有启用渠道 |
| 定时概览 | 每日或每周指定时间发送，沿用全局账号筛选和通知时区 |
| 可视化管理 | 查看额度快照、调整设置、测试推送、查询发送回执 |
| 外部消息 | 可选转发 Did Codex Reset 的重置预告与完成记录，默认关闭 |
| 持久记录 | 多账号、多窗口独立判断，去重、限速和重试记录跨重启保留 |

## 安装

### 在 Magpie 中添加

打开 Magpie 的 **插件 → 添加插件**，填写：

```text
github:real-LEONEAST/magpie-quota-notify
```

安装后，从 Magpie 桌面版或网页版左侧打开 **额度通知设置**。页面跟随 Magpie 的浅色与深色主题。

插件内置列表和侧栏图标。精简“已安装”列表中的通用说明和“选项”入口，可使用 [Magpie v0.1.3336 宿主补丁](compat/magpie-v0.1.3336/README.md)。

### Docker / NAS

在 NAS 终端执行，`magpie` 替换为实际容器名：

```sh
docker exec magpie /magpie plugin add github:real-LEONEAST/magpie-quota-notify
```

页面通过 Magpie 的页面代理访问，**无需新增 Docker 端口映射**。首次安装后若侧栏尚未出现入口，重新加载插件或刷新 Magpie 网页。

## 首次配置

1. 打开 **额度通知设置**，点击需要的渠道按钮。
2. 按下表填写接收信息。分类、分组、服务地址和请求头位于“更多渠道设置”。
3. 选择额度读取方式：**主动刷新**会查询最新额度；**使用缓存**读取 Magpie 现有数据。如果缓存长时间没有变化，选择主动刷新。
4. 选择检查间隔、阈值和提醒规则，点击 **保存并应用**，无需重启插件。
5. 点击一次 **测试推送**，在手机端确认接收。页面的“服务已接收”表示推送服务接受了请求。

新安装未配置渠道时不会发送通知。升级会保留原有阈值和通知开关，不会自动开启新的提醒或外部转发。

| 渠道 | 填写内容 |
| --- | --- |
| MeoW | 手机端推送昵称 |
| Bark | 设备 Key，可选自建服务地址 |
| [PushPlus](https://www.pushplus.plus/doc/guide/api.html) | Token，可选群组编码，使用微信渠道 |
| [Server酱](https://github.com/easychen/serverchan-sdk) | Turbo 或 Server酱³ 的 SendKey，按密钥类型选择对应接口 |
| [Telegram](https://core.telegram.org/bots/api#sendmessage) | Bot Token 和个人／群组 Chat ID；机器人需已进入对应会话 |
| Webhook | HTTP 接收地址，可选请求头；请求正文包含 `title`、`body` 和结构化 `event` |

每个已保存且启用的渠道都有 **测试此渠道** 按钮；页面底部的 **测试推送** 会测试全部启用渠道。测试推送独立于事件和账号筛选。

## 全局通知规则与合并

所有启用渠道共享事件筛选、账号选择、阈值、恢复提醒、同轮合并及定时概览设置。选定的通知内容统一分发到各渠道。

- **全部事件**：沿用所有已开启的提醒；取消后，分别勾选额度不足、耗尽、恢复、重置前提醒、外部消息和定时概览。
- **全部账号**：包括以后新增的账号；取消后，只接收勾选账号的额度提醒和概览。账号列表来自最近一次额度检查。
- 外部重置消息没有本机账号归属，只按事件筛选。
- **同轮消息合并**默认开启。同一次额度检查中，先应用全局事件和账号筛选，再把多项额度变化合并为一条，分发到所有启用渠道；不同轮次、外部消息、测试推送和定时概览分别发送。
- 修改全局规则会保留渠道编号，并应用到尚未发送的消息；更换收件人、密钥或发送地址时，旧目标的排队消息取消。

合并通知按账号列出触发原因与额度。Plus 显示 5 小时和周额度，Pro 类套餐显示周额度。Telegram 超长消息按平台长度限制分段发送，重试和重启会从未完成的分段继续。

## 定时概览

在 **全局通知规则 → 定时概览** 中启用，可选择每日，或每周的一个或多个星期，以及发送时间。默认关闭，时间使用现有通知时区。

概览包含最近一次读取的账号额度、重置时间、读数时间及读取异常。全局“定时概览”事件开关和账号筛选共同决定内容，所有启用渠道接收相同概览。

同一日期的同一发送时段只入队一次，记录跨宿主和重启保留。短暂重启允许在设定时间后 5 分钟内补发；更早错过的概览不补发。已入队概览在一小时后过期。

## 提醒规则

| 设置 | 选项与行为 |
| --- | --- |
| 检查间隔 | 1 / 5 / 10 / 30 分钟，或自定义 1～60 分钟 |
| 剩余阈值 | 1～3 档，从大到小排列；提供 50 / 20 / 10% 和仅 10% 预设 |
| 恢复通知 | 关闭 / 每次 / 用完后；5 小时与 7 天分别设置 |
| 重置前提醒 | 关闭 / 每次 / 有余量 / 用完后；每周期一次 |
| 提前多久 | 5 小时：30 分钟 / 1 小时 / 2 小时；7 天：6 小时 / 12 小时 / 1 天 |

- **阈值提醒**：每档每周期一次；一次检查跨过多档时合并为最紧急的一档，耗尽通知优先。
- **每次恢复**：确认进入新周期，且上一周期有使用时通知。
- **用完后恢复**：耗尽后读到有效剩余额度时通知，也保留周期内恢复的判断。
- **有余量时预告**：仅当剩余额度高于最后一档阈值时，发送重置前提醒。
- **用完后预告**：仅在耗尽时提醒预计即将恢复。

提醒按检查间隔触发。恢复由新的有效读数确认；失效、回退、未刷新或时间倒退的读数不会用来确认恢复。未识别周期的窗口仅提供耗尽后恢复通知。

有效读数时间、通知时区和接口地址可在 **更多设置** 中调整。

## 外部重置消息

在提醒设置中开启 **外部重置消息 → 启用转发**，可接收 [Did Codex Reset](https://didcodexreset.com/) 提供的预告和新完成记录。该功能默认关闭，使用[公共 API](https://didcodexreset.com/api.html)，不需要 API Key，也不向该服务发送本机账号或 Magpie 网关密钥。

- 默认每 5 分钟检查，单次最多读取三页，遵守接口的 `Retry-After`。
- 首次开启可推送当前尚未到期的预告；已有完成历史只建立基线。
- 普通记录按 `signalId` 去重，时间、范围或置信度变化时发送更新。聚合完成记录按完成时间、重置类型和影响范围去重，上游 ID 变化时只转发一次。
- 只有日期的排期显示为时段；过期或已履行的排期不作为当前预告。
- 外部消息提供第三方重置预告与完成记录；本机账号恢复由额度读数独立判断。
- 关闭后取消尚未发送的外部消息；接口失败不影响账号额度监控。

## 数据保存与升级

设置与运行数据保存在 Magpie 配置目录，独立于插件源码：

| 文件 | 内容 |
| --- | --- |
| `quota-notify-settings.sqlite` | 页面设置、渠道配置、测试请求、详细发送回执 |
| `quota-notify-state.json` | 额度快照、窗口状态、待发送消息、去重和限速记录 |
| `quota-notify-lock.sqlite` | 多宿主互斥，不保存额度内容 |

运行文件可能包含账号、推送密钥和通知内容，请妥善保管，不要上传到公开仓库。数据库保存实际渠道值，页面遮盖密钥不等于数据库加密。

升级前备份源码、原 Options 和上述数据文件。SQLite 数据库应使用一致性备份，或暂停 Magpie 后复制；存在 `-wal`、`-shm` 文件时一并保留。

首次迁移旧版时导入原 Options，之后以设置数据库为准。更换安装来源时也需保留原 Options，同一插件不要同时启用多个来源。确认新来源正常后再移除旧入口；回退旧版时一并恢复相应配置和状态备份。

升级到 v0.4.0 后重新启动 Magpie，让所有宿主使用同一版本。旧渠道沿用原编号，设置页首次保存后持久保存固定编号；原设置、通知记录和待发送任务保留。

早期本机 v0.4.0 的渠道级事件和账号筛选不再使用，首次保存时清理；已有全局规则、渠道凭据和编号保留。

页面服务默认监听 `127.0.0.1:3479`。桌面窗口连接本机服务，网页版通过 Magpie 的页面代理连接。原插件 Options 中的 `uiPort` 可自定义端口，端口修改后需要重新加载插件。

## 兼容性与测试

**v0.4.1** 在 Node 24 和 Windows Bun 1.4.4 各通过 90 项测试。离线回放验证旧版去重记录及聚合完成 ID 变化，隔离 Chrome 验证桌面入口、网页代理、深浅主题切换、设置保存、模拟推送和窄屏布局。Windows 客户端待实机验证。

**v0.4.0** 在本机通过 Node 24、Windows Bun 1.4.4 模拟接口测试，并使用 Chrome 验证全局规则、六种渠道的相同通知内容、单渠道测试、定时概览与重启去重。

**v0.3.1** 已在 **Magpie v0.1.3336 / Linux Bun 1.4.4** 的 NAS 环境验证 GitHub 安装、真实页面、设置即时应用及原配置和历史保留。Plus / Pro Lite 通知格式已用 NAS 缓存读数验证；真实 MeoW 手机接收已在 v0.3.0 验证。Bun 版本声明见 [package.json](package.json)。

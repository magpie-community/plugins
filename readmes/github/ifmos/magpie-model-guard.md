# Magpie Model Guard

Magpie 插件：**模型级与账号级的降智检测**、业务回复模型判断与供应商侧保护。探针经 Magpie 网关的 Chat Completions 接口发出，不绑定供应商或账号体系，任意 `provider/model` 可用；检测不通过或业务回复命中规则时，通过请求门禁、路由组同步和供应商侧接管限制后续请求。

当前版本 `0.10.1`，遵循 SemVer；逐版本变更见 [GitHub Releases](https://github.com/ifmos/magpie-model-guard/releases)。

## 功能总览

- **模型降智检测**：定时使用可自动判分的探针题检测目标模型，连续失败后拦截后续请求。内置「糖果推理」，内置与自定义题都可编辑题目、预期答案和判分规则（数字 / 包含 / 精确 / 正则）；支持固定间隔与分阶段调度、全局默认、单模型覆盖、每日探针预算，并可指定探针的思考强度（`reasoning_effort`）。
- **请求门禁与路由组隔离**：门禁中间件按目标状态直接返回 403；显式路由组用原生 `off` 排除禁用成员，自动组临时物化为受管组，健康成员继续承接业务请求；恢复时只撤销 Guard 添加的停用项。
- **Codex 账号监测**：从本机 Magpie 登录中为每个 Codex 账号指定独立检测模型，连续失败后停用该供应商账号，复测通过后恢复；不修改 Gateway Key 白名单。
- **业务回复模型判断**：按业务回复中上游实际返回的模型（含 Gemini `modelVersion`）匹配 exact / contains / glob / regex 规则，命中后禁用目标、改道后续请求或只写保护日志；区分全局规则与目标覆盖。
- **供应商侧保护**：接管选定自定义供应商的协议地址，客户端继续使用 Magpie 原地址、Key 和模型 ID；Guard 在交付回复前判定实际模型，在未交付范围内有界重试，并可恢复原始地址。
- **控制台**：本机与临时远程控制台，覆盖监测目标、Codex 账号、检测题库、检测记录、保护日志和连接设置；历史列表按游标分页加载。
- **交付形态**：Go 单二进制后台（内嵌 Web 控制台）+ Magpie JS 插件宿主 + 网关门禁中间件；随附 macOS Intel / Apple Silicon、Linux AMD64 / ARM64、Windows AMD64 预编译二进制，无需安装 Go。

## 工作流程

```text
客户端 -> Magpie 网关 -> model-guard 门禁中间件 -> 上游模型
                         |
                         +-- 无禁用状态 ----------------> 直接放行
                         +-- 探针别名请求 ------------> 剥掉前缀后放行（防自拦截）
                         +-- 人工禁用 / failed / unavailable -> 403 拦截，不发往上游

定时调度器 --到达检测时间--> 用选中题目探针 --> 判分
    pass  -> state=passed，按 interval 排下一轮
    fail  -> 同题独立复测一次，两次皆错 -> state=failed（禁用），按失败复检间隔复测
    error -> state=unavailable（保守禁用），冷却后重试；不计为答错
```

门禁文件由 Go 后台在每次状态变化时原子重写，Magpie 在一秒内热加载。探针请求使用
内部别名 `model-guard-probe/<alias>/<model>`，门禁剥掉前缀后放行，避免探针被自己拦截。

**路由组隔离：** 插件启动的 Go 后台会同步本机 Magpie 的路由组配置。禁用具体模型后，显式组通过原生 `off` 排除该成员；自动组临时保存为同 ID 的受管组，健康成员继续处理业务请求。Manual 组会选择可用成员，全部禁用时停止转发。直接请求仍由中间件返回 403，探针继续按原始模型 ID 复测。

恢复时只撤销插件添加的停用项，保留用户原有停用、规则、权重等配置；未被用户修改的临时自动组恢复为原生派生组。状态变化立即触发同步，后台约每 10 秒检查配置变化和临时放行到期。同步异常在控制台明确显示，此时不能将直接请求门禁视为路由组隔离已成功。

路由组同步需要本机可执行的 `magpie`，默认读取 `$XDG_CONFIG_HOME/magpie` 或 `~/.config/magpie`；可通过插件选项 `magpieConfigDir`、`magpiePath` 指定配置与可执行文件，或直接启动后台时传 `-magpie-config <dir> -magpie <binary>`。配置目录须对应 Magpie 的 XDG 实例。独立启动未传 `-magpie-config` 时仅启用直接请求门禁。

Magpie 自身绕过中间件的内部请求不在直接请求门禁范围；中间件被关闭或加载失败时也无法提供该门禁。
此插件的判分只反映题目表现，不是模型身份认证。

## 安装

### 从 GitHub 安装（无需 Go）

在 Magpie 的 GitHub 插件安装入口填写：

```text
github:ifmos/magpie-model-guard
```

也可通过 CLI 安装：

```sh
magpie plugin add github:ifmos/magpie-model-guard
```

路由发现子进程只跳过 Model Guard 自身的后台启动，保留其它供应商和账号插件；CLI 查询在文件锁外执行。插件后台随宿主管道关闭而退出，避免插件宿主异常结束后留下调度进程。

Magpie 的 RPC 宿主使用 `readline` 持续读取共享 stdin；插件仅监听其结束和关闭事件，不主动调用 `resume()` 或读取协议字节。


### 从源码构建

需要 Go 1.26+：

```sh
go build -o bin/model-guard ./cmd/model-guard
magpie plugin add /absolute/path/to/magpie-model-guard
```

开发目录需包含 `plugin/`、`bin/model-guard`、`package.json`。跨平台构建：

```sh
sh scripts/build.sh
```

（产物：`bin/model-guard-<platform>-<arch>`，插件会按当前系统自动选择。）

### 首次配置

1. Magpie 插件入口 →「打开本机 Model Guard 控制台」或「打开临时远程控制台（Cloudflare）」。
   远程入口自动下载经 SHA-256 校验的官方 `cloudflared`（也可用插件选项 `cloudflaredPath` 指定，
   或设 `autoInstallCloudflared: false` 关闭自动下载），建立临时 HTTPS 通道并返回一次性管理链接；
   链接十分钟内有效、只能使用一次，临时通道最长 30 分钟。管理链接视同管理员凭证，请勿分享。
2. 「连接设置」确认网关 URL 与 Key（本机默认 `http://127.0.0.1:3425` / `magpie`；插件直接从本机 `settings.json` 读取）。
3. 「监测目标」→ 展开「添加监测目标」→ 直接读取本机 Magpie 内部模型目录（包含设置为「仅通过路由组暴露」的供应商模型，排除外部 `group/*`、`auto/*` 别名）→ 搜索模型 ID / 供应商，勾选一个或多个目标 → 添加监测。
4. 点「重测」立即跑一轮，确认链路正常。

### 插件选项

插件包选项在 Magpie 的插件设置中填写，全部可选：

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `backendAddr` | 首次启动随机端口并持久化 | 后台管理 API 监听地址，仅接受 `127.0.0.1`、`localhost`、`[::1]` 加具体端口 |
| `dataDir` | `~/.config/magpie-model-guard` | 状态数据库、恢复账本与钩子握手文件所在目录 |
| `magpieConfigDir` | `$XDG_CONFIG_HOME/magpie` 或 `~/.config/magpie` | 读取 `logins.json`、`providers.json` 等本机配置的目录 |
| `magpiePath` | `PATH` 中的 `magpie`，其次 `~/.local/bin/magpie`、macOS 应用内路径 | 路由组同步和自动组发现使用的可执行文件 |
| `binaryPath` | 按平台选择 `bin/model-guard-<platform>-<arch>` | 覆盖后台二进制路径，缺失打包产物时回退 `bin/model-guard` |
| `cloudflaredPath` | 无 | 远程控制台使用的 `cloudflared` 路径 |
| `autoInstallCloudflared` | 开启 | 未找到 `cloudflared` 时是否下载官方版本并按 SHA-256 校验 |
| `gatewayURL` / `gatewayKey` | 读取 Magpie `settings.json`；Key 缺省 `magpie` | 首次「连接设置」的默认网关地址与 Key |

### 控制台列表

监测列表采用全宽展示，添加表单默认折叠；可按模型、供应商或原因搜索，并筛选已阻断、检测通过、等待复测或已暂停的目标。

模型名与供应商分行显示；路由状态与检测结果、策略与阶段、上次与下次检测时间分别集中展示。常用「重测」「策略」直接可见，禁用、临时放行、暂停检测和删除收在「更多操作」中；删除仍需确认。

长原因和长预期答案支持展开阅读，自动刷新保留展开状态、测试模型选择和监测列表的键盘位置。桌面表格保留固定表头，小屏幕改用带字段标签的卡片，无需横向拖动整张表格。

模型检测记录、Codex 账号检测记录和供应商保护日志采用服务端游标分页，点击「加载更多」读取更早记录；每批分别为 100、20、100 条。监测目标、题库与供应商配置仍整体读取，以支持筛选、批量操作和配置编辑。

三个历史接口（`GET /api/results`、`GET /api/codex/accounts/results`、`GET /api/supplier-events`）返回 `{ "items": [...], "next": "..." }`。下一批带上 `before=<next>`，`next` 为空表示末页；原有模型、题目与账号筛选保持有效。`limit` 限制每批大小，模型记录与保护日志最大 500 条、账号记录最大 50 条。游标使用稳定排序与数据库复合索引范围查询，避免深页 `OFFSET` 扫描；无效游标返回 HTTP 400。


## 检测规则

内置题库：

| ID | 题目 | 自动判分 | 规则 |
| --- | --- | --- | --- |
| `candy` | 糖果推理 | 是 | 默认期望数字 `21`；`121`、`21.5` 不匹配，可在编辑弹窗修改期望 |
| `repeat` | 逐字复述 | 否 | 人工评价 |
| `japan` | 知识覆盖 / 日本首相 | 否 | 人工评价 |
| `person` | 知识覆盖 / 人物 | 否 | 人工评价 |
| `svg` | SVG 创作 | 否 | 人工评价 |

「检测题库 → 编辑」可修改内置和自定义题目的名称、正文、预期答案、判分类型及是否参与自动检测。
保存后新探针使用新规则，重启不会覆盖编辑结果；内置题不可删除。新增题目使用「新建题目」。判分类型：

- `number`：匹配完整数字文本，拒绝将期望数字作为更长整数或小数的一部分；
- `contains`：回答包含期望关键字；
- `exact`：去除首尾空白后完全相等；
- `regex`：正则匹配（保存时校验）；
- 勾选「参与自动门禁」的题目才会影响模型状态。

一轮检测对目标的每道自动题各发一次请求；任一题失败会**独立复测一次**，两次皆错才判定
降智（`failed`，禁用）。网络错误、超时、HTTP 非 200、空回答、截断、预算耗尽均记为
`unavailable`：保守禁用但不计为答错，冷却（默认 15 分钟）后自动重试。

### 状态与操作

| 状态 | 含义 | 门禁 |
| --- | --- | --- |
| `unknown` | 从未检测 | 放行 |
| `checking` | 检测中 | 保留已有禁用状态 |
| `passed` | 上轮通过 | 放行 |
| `failed` | 降智（连续两次答错） | **403 拦截** |
| `unavailable` | 检测不可用 | **403 拦截**（保守） |
| `review` | 人工暂停 | **403 拦截** |

操作明确分离：

- **禁用模型**：设置持久化的人工禁用标记，业务请求返回 403，检测探针仍可访问。即使复测通过也不会自动解除人工禁用。
- **解除禁用**：清除禁用状态，不改变自动检测开关；下一轮检测失败仍会重新禁用。
- **暂停 / 恢复检测**：只改变定时调度，暂停检测不会解除已存在的禁用。
- **重测**：立即执行一轮检测，暂停自动检测时也可使用。
- **临时放行 15 分钟**：到期后继续执行原禁用策略。
- **删除目标**：移除监测和该目标的门禁。

自动检测造成的禁用在复检通过后恢复；人工禁用优先于检测结果。
旧版“停用”仅表示暂停检测，升级后保留这一状态；若要阻止业务请求，请点击新版“禁用模型”。

### 分阶段自动检测

可在「连接设置 → 全局分阶段调度策略」选择分阶段模式，点击「codex-guard 预设」填入下列间隔。已有配置升级后默认保持固定模式；也可在目标行的「策略」弹窗选择继承全局、固定模式或分阶段模式，并为该模型单独覆盖间隔。

| 阶段 | 默认等待时间 | 行为 |
| --- | ---: | --- |
| 正常检测 | 30 分钟 | 检测所选自动题 |
| 答错复测 | 2 分钟 | 复测原题，连续 3 轮答错才禁用 |
| 首次隔离复测 | 6 小时 | 保持禁用，复测导致隔离的原题 |
| 后续隔离复测 | 24 小时 | 隔离后再次答错，继续禁用 |
| 恢复确认 | 2 分钟 | 第一次通过保持禁用，第二次连续通过才恢复 |
| 检测不可用 | 30 分钟 | 立即保守禁用，中断恢复连续通过计数 |

六项间隔均可设置为 1–43200 分钟。单次超时和每日预算仍然生效。人工禁用不会被检测结果解除；原复测题被删除或取消自动判分时记为不可用，避免通过其它题目误恢复。

保存策略默认保留已经排好的 `next_check_at`；勾选「重新计算下次检测时间」才按当前阶段重新安排，正在运行的检测不重排。重启保留阶段、复测题和检测期限。固定模式仍使用单轮内立即独立复测一次、两次答错禁用、一次通过恢复的原有规则。


### 预算与超时

- 每模型每日探针请求上限（默认 120，可设 1–10000）；
- 单次请求超时默认 180s，`max_tokens` 8192；
- 固定模式默认检测间隔 30 分钟，可按目标设置 1–43200 分钟；
- 固定模式失败复检默认 60 分钟；分阶段模式按上表分别设置；
- 思考强度默认「不指定」，探针不发送 `reasoning_effort`，由模型使用自身默认；可在「连接设置 → 探针策略」选择 `none` / `minimal` / `low` / `medium` / `high` / `xhigh`，也可在目标的「策略」弹窗里继承全局、独立选档或退回模型默认；检测运行中修改强度（或调度模式）会丢弃该轮状态回写，避免用旧设置的判定更新目标；模型检测与 Codex 账号检测都按此处理。

### 业务回复模型判断

除了回答内容，Guard 还可以检查**业务回复**里上游实际返回的 `model`（Gemini 的 `modelVersion`）。回复模型命中规则时按动作处理：

| 动作 | 处理 |
| --- | --- |
| `disable` | 规则阻断目标，默认 30 分钟；探针通过不会提前解除，到期或手动解除后恢复 |
| `reroute` | 把真实模型加入改道集合，后续路由组避开该成员 |
| `record` | 只写保护日志 |

- 规则可按 `exact`、`contains`、`glob`、`regex` 匹配，默认不区分大小写；正则可用 `(?-i)` 关闭。
- 「连接设置 → 业务回复模型判断」配置全局模式、全局规则、改道保持和规则阻断保持时长；监测目标的「策略」弹窗可选择继承全局或自定义覆盖。
- 规则只判断业务回复，不判断降智探针：降智是持续性问题，定时探针仍有意义；上游实际模型路由是不确定的，单次探针只代表当次，不能用来推断下一次业务请求会落到哪个成员。
- 未接管的业务回复通过 Magpie 异步 `onResponse` 钩子上报，守卫进程在 `dataDir` 写入权限为 `0600` 的 `response-hook.json` 提供本地回环地址和控制 token；规则未启用时钩子直接跳过。宿主不支持 `magpie.hooks` 时，探针检测、直接门禁和供应商侧同步保护仍可运行。
- 异步钩子只能观察已完成的回复，`disable` / `reroute` 影响后续请求。需要当前请求先重试时，在「供应商保护」接管选定供应商。
- 改道集合默认保留 30 分钟（可设 1–1440 分钟），规则阻断默认保持 30 分钟（可设 1–1440 分钟），到期后路由组自动恢复。
- 探针检测记录与供应商保护日志相互独立：前者只保存探针回答与判定，后者保存保护启停、规则命中、重试和提交失败，可在「保护日志」查看。规则命中不再写入检测记录，也不再改写探针状态。
- 阻断状态本身共用一份：请求门禁、供应商代理和路由组隔离读取同一目标状态，避免两套判断互相矛盾。目标会标记阻断来源：`manual`（人工）、`rule`（业务回复规则）或 `probe`（降智探针）；探针通过只解除探针来源的阻断，规则阻断按自己的保持时间到期。

### 供应商保护（客户端配置不变）

打开「连接设置 → 供应商保护」，为选定供应商点击「启用保护」。链路变为：

```text
客户端 → Magpie（选 Key、路由、协议转换）→ Guard（回复判定与有界重试）→ 原始供应商
```

客户端继续使用 Magpie 原有的 Base URL、Key 和模型 ID。Guard 只接管 `providers.json` 中显式配置的自定义协议地址，以及一个用于识别恢复探针的 header；供应商凭据、模型、自定义 headers、`extraBody`、fallback、affinity 和代理配置仍由 Magpie 管理。Guard 转发 Magpie 已准备好的请求，重试保持同一已选凭据与请求体，不切换账号。

- 支持 Chat、Responses、Anthropic、Gemini 回复模型判定；辅助接口直接转发到该供应商原地址。`decide` 地址也可接管转发，不执行回复模型判断。
- 「最多尝试次数」包含首次请求，范围 1–5。`disable` / `reroute` 命中时在尚未交付的范围内重试；`record` 首次命中即记录，不重试。Responses WebSocket 只在可确认中断当前响应时重试；终态坏回复会被拦截并关闭连接，需要客户端重连。
- 重试耗尽后提交阻断或改道动作，再返回可重试错误；Magpie 仍可按其原生 fallback 规则选择其他供应商。供应商保护的改道隔离原请求实际选中的 `provider/model`，保护日志保留供应商返回的真实模型名。
- 单模型判断支持 `modelIDs` / `modelWires` 映射；多个监测目标映射到同一 wire 名时使用全局规则，避免错误禁用其中一个。恢复探针凭会话标记绕过业务拦截，标记在发给供应商前移除。
- Guard 使用供应商当前代理、每 Key 代理和 TLS 设置，未指定时沿用 Magpie 全局代理、环境变量或系统代理。账本仅保存受管地址和恢复元数据，不复制供应商 Key 或代理凭据。
- 地址修改使用持久化写前账本和原子替换；重启时恢复未完成事务，并在端口显式更换时重绑受管地址。除插件专用的 `X-Model-Guard-Session` 外，外部修改受管字段会显示冲突并停止该入口转发，保留用户修改及恢复信息；该保留头由 Guard 独占，漂移不阻断路由或恢复，恢复时会清理其全部大小写形式。
- 同步判断过的回复按回复 ID 去重，避免 Magpie 异步钩子再次执行动作。已保护供应商的直接请求统一跳过异步判断，即使供应商未返回 ID、Magpie 生成了新 ID。原生钩子没有实际供应商信息；供应商未返回 ID、ID 被转换或超出前缀窗口时无法可靠关联。因此存在供应商保护期间，无法关联的 `group` / `auto` 回复暂停异步判断；组内受保护供应商仍同步判断，未保护供应商的直接请求仍可异步判断。
- 订阅类插件、没有显式自定义协议地址的供应商不在接管范围。地址中的查询参数、用户信息或片段会被拒绝，避免凭据写入恢复账本；Azure OpenAI、Google Vertex AI、Bedrock、OpenCode，以及 Vercel / Cloudflare 决策端点也暂不支持接管，控制台会显示原因。远程 Magpie 因依赖原生端点重写，单独列为不支持接管并禁用保护入口，不作为配置冲突提示。额外尝试会在供应商侧计费，但不会作为独立调用计入 Magpie 的用量统计。

**停用或卸载前，先点击每个已保护供应商的「恢复原始地址」。** Guard 停止运行时，仍指向 Guard 的供应商会连接失败；不会自动绕过保护。恢复只撤销 Guard 管理的字段，保留其他配置更改。建议先在一个供应商上验证，再逐个启用。

## Codex 账号监测

「账号监测」读取本机 Magpie 的 `logins.json`，为每个 Codex 登录单独指定一个原生 `codex/...` 模型。检测请求通过 `X-Magpie-Account` 固定到该账号，不允许回退到其他账号；连续两次失败后，Guard 在 Magpie 供应商账户中停用该账号（与非当前账号一样关闭 `on`，对当前账号同时暂停），而不是修改 Gateway Key。到达隔离间隔后自动复测，通过一次即恢复。检测不可用、429、超时或 HTTP 错误只安排重试，不算降智。

- 停用和恢复只修改 `logins.json` 的账号启用状态，不删除登录、不修改 Codex 凭据，也不读写 `caller-keys.json`。因此不会与 Gateway Key 白名单产生冲突。
- 复测必须先让账号可被 Magpie 路由。Guard 会在复测请求前把该账号短暂启用（通常数秒），请求结束后立即恢复停用；只有复测通过才保留启用。这段窗口内业务请求可能命中该账号，接受不了时可关闭该账号的自动复测。
- 停用当前正在使用的账号需要另一个已启用账号承接流量；Guard 会自动启用一个备用账号，复测通过后再恢复备用账号的原状态。只有一个 Codex 账号、或所有其他账号都被隔离时，无法停用最后一个可用账号，界面会显示失败原因。
- 同名 Codex 账号无法通过 `X-Magpie-Account` 唯一固定，Guard 会拒绝为这类账号执行检测，避免测到另一个账号。账号从 Magpie 消失后保留隔离记录作为墓碑；重新登录同稳定 ID 账号后继续检测。
- 账号探针使用全局时间策略：正常间隔、错误复测、首次/后续隔离、不可用冷却；连续 2 次失败隔离，单次通过恢复。思考强度沿用「连接设置 → 探针策略」的全局值（账号级暂不单独覆盖）。检测结果与模型监测、供应商保护日志相互独立。

## 数据与安全

后台监听地址默认在首次启动时随机分配并持久化到 `dataDir`，重启复用；已保存端口被占用时启动失败而不是漂移。多实例或端口冲突可在插件包选项中设置 `backendAddr`：`127.0.0.1:<端口>`、`localhost:<端口>` 或 `[::1]:<端口>`（1–65535）。

- 状态存于 `~/.config/magpie-model-guard/model-guard.db`（SQLite）；
- 管理 API 仅监听回环地址；插件宿主持有控制 token，控制台通过一次性票据链接换取 30 分钟 HttpOnly 会话 Cookie，管理域名不匹配时拒绝票据；
- 远程临时通道由 Cloudflare Quick Tunnel 提供（无 DNS 配置），隧道目录随会话清理，通道关闭即吊销全部会话；
- 探针只经过 Magpie 网关，不持有上游供应商凭据；路由同步只管理 `providers.json` 中受影响组的字段，保留供应商与未知配置数据。
- 路由恢复账本和待提交事务存于插件 SQLite，重启继续处理隔离与恢复。自动组由插件临时物化，其受管字段被外部改写时以当前配置为新基线继续隔离，恢复时只撤销插件添加的停用项；显式组的受管字段被外部修改时停止覆盖该组，并显示组 ID 与冲突字段，可在 Magpie 中恢复受管字段，或解除对应监测目标让同步释放该组。
- 同步使用插件侧文件锁、写前字节检查和原子替换；Magpie 原生配置写入不共享此锁，因此应避免同时编辑正在同步的组。原生程序在最后检查与替换之间的并发写入仍存在竞争窗口。
- 临时保存的自动组在隔离期间使用保存的成员列表；完全恢复后返回 Magpie 动态发现。禁用或卸载插件前，先解除禁用或删除相关监测目标，等待路由同步恢复；直接退出后台会保留隔离配置。
- 业务回复模型判断的钩子只上报请求模型、实际模型、协议和 agent，不上报消息正文或凭据；本地握手文件 `response-hook.json` 权限为 `0600`，只用于本机回环 API。

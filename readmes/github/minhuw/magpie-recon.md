# 储备

magpie 窗口里的一页。不改 magpie 本身。只读两个文件：

- `usage.jsonl`：每次调用的时间、token、网关钥匙、订阅账号
- `quota-history.json`：每个账号每个窗口的剩余百分比、窗口起点、reset

额度历史是 JSON，不是 JSONL。magpie 写在配置目录里，和 `usage.jsonl` 放在一起（默认 `~/.config/magpie`，或 `$XDG_CONFIG_HOME/magpie`）。

插件另在同一目录保存自己的 `reserve-membership.json`，只含参与统计的账号标识和选择变更时间。它不修改 Magpie 的账号配置、额度历史或用量日志，也不读取账号凭据。

## 安装

在要看的那台 magpie 上：

```sh
magpie plugin add github:minhuw/magpie-recon
```

在插件页打开它，侧边栏会出现「储备」。第一次打开会稍等，页面要等本机服务起来再跳过去。

配置目录不在默认位置时，插件行的 Options 写成：

```json
{ "port": 3478, "dir": "/你的/magpie配置目录" }
```

`dir` 要是绝对路径。空字符串表示用默认目录。环境变量 `MAGPIE_RESERVE_DIR` 同样是这个目录。

## 页面

页面顶部按 Codex、Claude 分别给出使用建议：用量偏快时显示应减少的比例，有余量时显示可增加的比例，节奏接近目标时建议保持。旁边列出按当前节奏和建议节奏估算的总日消耗；单位是全部参与账号合计的「百分点 / 天」，不是请求数或 token 数。

建议以持续使用到各账号本次周额度重置为目标，默认每账号预留 3 个百分点。顶部「重置时目标预留」可选 0、3、5、10 个百分点，选择后会重新计算并保留在页面 URL 中。「建议依据」说明计划截止时间、有效观测时长和已识别的时段规律。

单账号、恒定速率时，目标日消耗为 `(剩余额度 - 预留百分点) / 距离重置天数`，调整比例为 `目标日消耗 / 当前估计日消耗 - 1`。例如剩余 30%、3 天后重置、预留 3 个百分点，目标为每天 9 个百分点：当前每天消耗 15 个百分点时建议减少约 40%，每天 5 个百分点时可增加约 80%。接近目标的 ±10% 时建议保持；若预计会提前耗尽，仍会提示减速。

主图按 Codex、Claude 分开显示前 15 天的实际剩余和后 15 天的预测，只使用每个账号的周额度窗口。约 7 天的窗口会被识别为周额度；5 小时等短窗口不参与周额度曲线，但短时额度偏紧或耗尽时会阻止提速建议。纵轴为总账号额度：一个账号满额是 100%，四个满额账号是 400%，五个是 500%。例如两个账号分别剩 30% 和 100%，图上合计剩余 130%，总容量 200%。灰色点线表示当时的总容量，缩放时纵轴按所看时段调整。

「参与预测的账号」中可以取消勾选已删除、停用或不再参与统计的账号，也可以重新纳入。选择会保存在本机，下次打开仍有效；它只改变本插件统计，不会停止 Magpie 向该账号发送请求。额度历史和调用日志不是当前启用名单，所以插件不会仅凭闲置或旧读数猜测账号已删除，需要在此明确排除。

新账号首次出现在额度历史后自动纳入，从首次实际记录时间起增加容量，不倒填到周窗口起点。新增账号只有一条读数也不会清空已有需求估计。排除账号从选择时刻起减少未来容量，历史用量仍保留；重新纳入时保留中间排除的时间段。菱形标记说明「首次记录」「纳入统计」「排除统计」或缺少当前额度，避免把容量变化误看成消耗或重置。这里记录的是插件观察和用户选择的时间，不是实际开户或删除时间。

预测先估计供应商总需求，再按近期账号分配比例模拟消耗、账号间转移及各自重置。训练按每个历史时刻的成员集合汇总需求，不要求新账号覆盖旧账号的全部历史；加入后未知的观测区间仍会跳过。移除账号不直接抹掉过去的需求，未来将这部分需求分配到当前参与账号。没有参与账号时，仍可查看历史曲线和重新选择账号，不会误报为额度全部耗尽。

历史线按小时显示，同时保留小时内的首值、最低值、最高值和末值；即使同一小时先耗尽再重置，0% 低点也不会被日末读数覆盖。实线按已知读数阶梯连接；没有记录到的耗尽不会被补画为 0%。

图表支持「近 48 小时」「近 7 天」「全部」范围切换，Codex 和 Claude 的时间轴同步。使用加减按钮缩放、左右按钮平移，最小范围为 1 小时。也可拖动图表平移，按住 Ctrl / ⌘ 滚轮围绕指针缩放，悬停或轻点查看时间、总剩余额度和当时的总容量。聚焦图表后，方向键平移，`+` / `-` 缩放，`Home` 恢复全部范围。

估计使用最近 28 天可比较的原始额度读数，按小时整理，以半衰期 24 个有效观测小时的指数加权平均（EWMA）响应近期变化。所有账号额度归零后的停用不当作需求下降；额度可用时的真实零消耗会降低估计。跨重置、读数回升或缺测的区间不补成零消耗，未来时间戳的读数不参与计算。有限历史的权重会归一化，避免开头几秒钟的突发样本主导整个估计。

有足够密集、完整的重复观测后，再加入日内或每周规律；每个时段至少需要两个完整重复，稀疏规律向平坦曲线收缩。长于两小时的读数间隔可用于估计总体速率，但不用于学习时段规律。样本质量标记只反映观测覆盖程度，不是校准过的概率，也不代表已回测证明更准确。

多账号预测假设容量相同、请求可在账号间切换：某账号耗尽后，需求转移至其余可用账号；各账号按自己的时间恢复到 100%，再继续消耗。不同订阅档位或不能互相切换的账号需要结合实际容量判断。建议通过模拟找到在计划范围内保留余量的最大用量倍数，而不是只用总余额除以最近一次重置时间。

- 未来 15 天内预计所有账号同时无额度：显示「会耗尽」和首次耗尽时间；较早发生过一次重置不会遮住之后的耗尽。
- 已有账号耗尽：顶部说明已耗尽账号数量及后续流量转移假设；所有账号都已耗尽时显示等待最早一次重置。
- 不足 20 分钟可比较观测时不外推耗尽时间；不足 6 小时有效观测时，只给可计算的日预算参考，不报增减百分比。
- 额度历史不是固定频率更新的心跳：Magpie 的部分已保存账号需要手动刷新额度。读数超过 30 分钟本身不停止建议；只有较早的读数之后又有实际调用、余额尚未确认时，才暂停精确建议并提示在 Magpie 用量页刷新账号额度。本页「刷新」只重新读取现有记录，不向供应商查询。
- 读数之后没有相应网关调用记录时，沿用最后余额作为预测起点，不凭空扣除闲置期间的额度，并注明快照时间。这是假设余额未变，不证明其他客户端没有用量；在其他客户端使用过这些账号时，应先在 Magpie 刷新额度。
- 有足够观测但当前用量接近零时，给出日预算参考，不显示无限大的提速百分比。
- 预测不包含经过校准的概率区间。参数和真实预测改进仍需用实际历史做滚动回测验证。

展开的「账号窗口」表格可检查单个账号的剩余、耗尽预测和 reset。

第二行是 30 天每日用量。柱高使用「账号当量」：每个账号取最长窗口，把当天剩余百分比的下降相加，再除以 100。例如账号 A 下降 30%、账号 B 下降 20%，当天合计 0.50 账号当量。reset 造成的回升不算消耗；当天缺少任一账号的读数时，账号当量显示未知。

默认选中今天。点击、触摸或用键盘选择其他日期，可查看当天的 token 和账本记录的 API 等价成本。token 和成本保持原始单位，不按订阅价格换算；账本不完整或成本缺失时会明确标出。

服务只听 `127.0.0.1`，并且核对 Host。页面跑在 magpie 的沙箱里，自己不能发请求，只能把框架导航到这个服务。

# GPTFree号池（magpie-gptpool）

*Magpie 插件｜把多个 ChatGPT 账号变成自动轮询、自动换号的本地生图号池*

> **本插件是 [`yang0/magpie-gptfree`](https://github.com/yang0/magpie-gptfree) 的分支，已改名为
> `magpie-gptpool` 独立维护。**
>
> 基于上游 **0.6.6 / commit `5ab9b99`**（MIT，见 [LICENSE](./LICENSE)）。我们改了什么、
> 为什么改、怎么跟上游同步，全部写在 **[FORK.md](./FORK.md)** 里，简要清单：
>
> | 方向 | 改动 |
> | --- | --- |
> | 选号 | 按剩余额度加权轮转（nginx smooth WRR）+ 连续失败熔断（10min→1h）+ 额度归零后按上游重置时间自动复检 |
> | 判死 | 四条规则（`auth` / `never` / `stale` / `marked`），分类计数，可整组复检或删除 |
> | 请求预算 | 单次 35s / 整单 55s 硬超时，额度耗尽的 400 自动换号而不是整个请求失败 |
> | 图片桥 | 新增 `lib/chat-image-bridge.mjs`，把 `chat/completions` 上的图片模型桥到 `/images/generations`；正文默认「内联图 + 一行裸地址」，面板里可切；`n>1` 并发多打几次真的出多张（部分成功也返回） |
> | 图片管理 | 面板「图片」tab：总张数 / 总占用 / 近 14 天柱状图、排序与日期筛选、分页缩略图（**列表 / 网格两种视图**）；勾选 / 拖动框选 / Shift 连选后批量删除。保留天数（1–90，默认 7 天）、自动清理时段（默认全天）、「立即清理早于 N 天」和**清理日志**都在「设置」tab |
> | 统计 | 按天记成功/失败（生图与文本分开）、失败原因分布、限流起止时间；趋势图可在 **按日 / 按周 / 按月 / 按年** 之间切换（账本保留 400 天） |
> | 导入 | 分隔符 `----` / `---` / `--` 都认，同一文件可混写；五字段仍要求 `----`（见下方「支持的账号文本格式」） |
> | 面板 | 导航 = **总览 / 图片 / 设置**，右侧常驻「+ 导入账号」主按钮；号池为空时直接给导入引导；账号池按状态分组 + 搜索 + 排序 + 批量删除；额度表点表头排序；Token 徽章只认上游的真实反馈（`已确认` / `未确认`），不再拿本地解码 JWT 当结论 |
>
> 安装时请用 `https://github.com/puaicg/magpie-gptpool`（本仓），不要用上游地址 ——
> 上游的提交会覆盖上面这些改动。细节见 FORK.md「怎么装、怎么升级」。
>
> **和上游的关系**：包名、仓库、GUI 端口（`37990`）、页面标题都换成了自己的；但
> Magpie 配置里的 provider id 仍是 `gptfree-pool`，模型名仍然是

## 这玩意儿能干什么

一个 Magpie 插件，把**一堆便宜的 GPT 普号**变成**一个会自动轮询、自动换号、自动重登的号池**：

- **批量导入**：一行一个账号，粘进文本框就行；格式不对可以直接改，不用重新上传文件。
- **多账号真轮询**：每个账号单独出现在 Magpie 里，可单独启用、可设为首选；某个号挂了，自动切下一个。
- **生图真能用**：不只聊天，文生图、改图都能跑，普号的图片额度一样用得上。图片模型覆盖 **GPT Image 2** 与 **GPT Image 2.6 全系列**（`gpt-image-2` / `gpt-image-2.6` / `gpt-image-2.6-flare` / `gpt-image-2.6-sunburst`），2.6 系列还支持生成 GIF 动图。
- **额度看得见**：首页就是**一张总览**——六个数字（当前账号 / 可用 / 限流 / 剩余额度 / 成功 / 失败）、调用趋势、失败原因和账号列表放在同一页，往下滚就是明细，不用来回切页。
- **图片管得住**：生成的图默认留 7 天、每小时自动清一次；面板「图片」页能看占用和近 14 天产出、按日期筛、框选后批量删；「设置」页配保留天数与清理时段，还能翻**清理日志**看每次到底删了多少张。
- **数据不出本机**：凭证加密保存在你自己的电脑上，界面只显示打码邮箱。

> [!IMPORTANT]
> 额度数字全部实时读取自 ChatGPT 官方。**没检测就显示"待检测"，查不到就显示"查询失败"，绝不编造。**

## 三步装好，有手就行

### 第 1 步：在 Magpie 里安装插件

打开 Magpie，点顶部 **「插件」** → 切到 **「发现」** → 在最底部的输入框里填入仓库地址：

```
https://github.com/puaicg/magpie-gptpool
```

点右边的 **「安装」**，稍等几秒搞定。

![在 Magpie 插件页填入 GitHub 仓库地址一键安装](docs/images/install-plugin.jpg)

> [!TIP]
> 简写 `github:puaicg/magpie-gptpool` 同样可以被识别，填哪一个都行。

> [!WARNING]
> 填 `yang0/magpie-gptfree`（上游原版）也能装上，但那是**没有下面这些改动的原版**。

### 第 2 步：导入账号

安装后，点顶部 **「GPTFree号池」** 进入号池页面，默认停在 **「总览」**。导入入口有两个，都在页面顶部：

- 导航栏**最右边**那个主色按钮 **「+ 导入账号」**（常驻，任何时候都点得到）；
- 号池还是空的时候，总览页中间那张引导卡上也有一个 **「+ 导入账号」**。

进去以后：

1. 点 **「选择 TXT 文件」**（或直接把文件拖进虚线框），文件内容会**自动填进下面的文本框**；
2. 如果某几行格式不对，**就在文本框里直接改**——不用重新上传，改完点「检查账号格式」看预览；
3. 勾选「跳过格式错误行，仅导入有效账号」（可选），填好代理（需要的话），点 **「导入并授权入池」**。

![在 GPTFree号池页面选择 TXT 或直接粘贴账号后导入](docs/images/import-accounts.jpg)

> [!TIP]
> 分隔符写 `----`、`---` 或 `--` 都行：从别的工具复制出来的 `邮箱--密码--2FA密钥` 可以直接粘，不用先替换成四个连字符。完整格式见下面「[支持的账号文本格式](#支持的账号文本格式)」。

全程后台自动登录，**不启动浏览器、不弹网页**。成功的账号会**自动分别同步到 Magpie 的供应商列表**，不用再手动添加。

### 第 3 步：看额度、开用

导入完回到 **「总览」**，一页从上往下就是：六个统计数字 → 调用趋势 + 失败原因 → 失效账号分类 → 账号列表。

- **六个数字**：当前账号 / 可用账号 / 限流账号 / 剩余额度 / 成功调用 / 失败调用，一眼看全局。
- **调用趋势**：右上角可切 **按日（近 14 天）/ 按周（近 12 周）/ 按月（近 12 个月）/ 按年（近 2 年）**，每根柱子顶上直接标着「成功数 / 失败数」，不用悬停也能读。账本按天记、保留 400 天，所以「按年」最多两年。
- **失败原因**：近 7 天按错误类型排行（上游限流、生图超时……），一眼看出是号不够还是网络不通。

![总览：六个统计数字、调用趋势（柱顶带数字）、失败原因分布](docs/images/quota-stats.jpg)

- **账号列表**：按状态自动分成 **可用 / 限流中 / 待检测 / 额度查询失败 / 需续期 / 已失效** 六组，每组带数量、点标题可折叠，右边「选本组」一键把整组加入选择。
- 列表上方有 **搜索**（打码邮箱或槽位号）、**分组开关**（按状态分组 / 不分组）、**排序**（额度高低 / 最近成功 / 失败次数 / 槽位号），点表头也能排序。
- **批量栏常驻**：勾选账号左侧复选框后，可以「批量检测额度」或「批量删除」。
- 每个号有两个标签，各管一件事：**`Token 已确认` / `Token 未确认`** 说的是 Token 上游认不认（只看真实证据：额度检测通过或出过图），**`额度可用` / `已限流` / `待检测`** 说的是额度状态；还剩多少额度看右边那一列。限流的号也可能显示 `Token 已确认`——那说明 Token 没问题，只是额度用完了。

![账号列表：按状态分组、每个号带 Token 与额度两个标签、批量栏常驻](docs/images/pool-overview.jpg)

- 回 Magpie 正常选模型聊天 / 画图即可，轮询和故障转移插件全接管。
- 画出来的图会落到 `/config/images`，导航里的 **「图片」** 就是管理页（占用、近 14 天产出、删图），见下面「[「图片」页是什么](#图片页是什么)」；保留天数、清理时段和清理日志在 **「设置」** 页。

## 支持的账号文本格式

每行一条，分隔符写 `----`、`---` 或 `--` 都认（同一文件里混着写也行）：

| 格式 | 示例 | 说明 |
| --- | --- | --- |
| 标准三字段 | `邮箱----密码----2FA密钥` | 最常用，直接导入 |
| 标准三字段（2 连字符） | `邮箱--密码--2FA密钥` | 从别的工具复制过来的 `--` 格式也能直接导入 |
| 带邮箱链接 | `邮箱----密码----2FA密钥----https://mail.xxx.store/...` | 第四段当邮箱链接识别，只用前三段登录，不会访问链接 |
| 带 Token | `邮箱----密码----2FA密钥----eyJhbGci...` | Token 有效就复用；过期会自动重新登录 |
| 五字段带 RefreshToken | `邮箱----密码----2FA密钥----eyJhbGci...----rt_...` | 兼容卡密导出格式，多余字段不外传 |
| 无 2FA | `邮箱----密码` | 能用，但平台额外验证时可能失败 |

> 五字段（Token + RefreshToken）请用 `----` 分隔：JWT 签名里本身可能出现 `--`，用 `--` 切会把签名切断，所以这种行会直接报格式错误，不会悄悄导错。

> [!WARNING]
> **不要提交真实凭证 TXT 到 GitHub，也不要把账号密码 / 2FA / Token 粘贴到公开聊天记录。** 本仓库已忽略 `accounts*.txt`、`pool.enc.json` 等敏感文件。

## 「总览」页是什么

一张看板，把号池的健康度摊开给你看：

| 卡片 | 含义 |
| --- | --- |
| **当前账号** | 号池里一共几个账号 |
| **可用账号** | 有 Token 且还有剩余生图额度（绿色高亮） |
| **限流账号** | 剩余额度为 0 或已触发限流 |
| **剩余额度** | 所有可用账号的生图剩余额度之和 |
| **成功调用** | 本机累计生图成功次数 |
| **失败调用** | 本机累计生图失败次数 |

下面接两张卡：**调用趋势**（柱顶直接标成功/失败数）和 **失败原因**（近 7 天按错误类型排行）。

再往下是 **失效账号分类**：登录失效 / 从未成功 / 长期失败 / 人工标记，点分类可以只把这一类选出来，整组复检或整组删掉。

最下面是**账号列表**：`账号 / 类型 / 状态 / 剩余生图额度 / 成功·失败 / 最近检测 / 操作`，每行可以「检测额度」「刷新授权」「移除」。

> [!TIP]
> 如果导入成功但额度一直显示"查询失败"，通常是登录和额度查询走的是两个不同域名，网络通路不一致。在页面顶部填好一个能正常访问 ChatGPT 的 HTTP(S) 代理，再点「刷新全部额度」即可。

## 「图片」页是什么

生成的图默认落在 `/config/images`，导航里的 **「图片」** 就是它的管理页（后面的数字是当前张数，没进过这页时显示 0，进一次就对上了）：

- **四个数字**：总张数 / 总占用 / 最早一张 / 最晚一张。
- **近 14 天柱状图**：每天生成了多少张，柱顶直接标数字。
- **手动清理**：列表可按大小 / 时间排序、按日期区间筛选、分页（每页 20 张，缩略图按需加载）。选中方式有三种——点复选框、**按住往下拖**连选、Shift 点另一行选一段；「全选筛选结果」会把**整个筛选结果（跨页）**一次选中，然后「删除选中」。
- **列表 / 网格两种看法**：右上角切换。列表省地方、适合核对文件名和大小；网格用大图，适合一眼找「上次那张」。切换不动数据，选中状态跟着走。
- 删除是**二次确认 + 逐条容错**：某个文件删不掉只会跳过并报原因，不会整批失败；单次最多删 500 个。
- 页头的 **「清理设置」** 直接跳到设置页 —— 保留天数、清理时段、按时间批量清理、清理日志都在那边。

![图片页：统计卡、近 14 天柱状图、筛选与批量清理](docs/images/images-manage.jpg)

网格视图：同一页数据换成大图排版，点卡片即选中，拖动照样能连选

## 「设置」页是什么

配置类和「一次删一批」的动作都收在这一页，图片页只管看图和删选中的：

| 区块 | 干什么 |
| --- | --- |
| **图片回复格式** | 图片模型经 `chat/completions` 回复时正文长什么样：图 + 地址 / 只要地址 / 只要内联图。客户端「复制」复制的是这段正文，所以要带一行裸地址 |
| **自动清理** | **保留** 1–90 天（默认 7 天）、**时段** 小时区间（默认全天，支持跨午夜 `22:00–06:00`）。超过保留期的图每小时最多清一次，且只在时段内跑 |
| **立即清理** | 不受保留天数和时段限制，删掉早于 N 天的图片，用来临时腾地方。这次清理不改全局保留天数 |
| **清理日志** | 每次清理留一条记录，见下 |
| **生图错误日志** | 每个账号失败留一条：时间、账号、错误码、上游原文，见下 |

设置存在本机 `~/.magpie-gptfree/settings.json`，**改完立刻生效、不用重启插件宿主**。对应的环境变量（`MAGPIE_GPTFREE_IMAGE_REPLY` / `..._RETENTION_DAYS` / `..._CLEANUP_WINDOW`）仍然优先，设了面板就置灰并写明原因——免得你改了不生效还以为坏了。

> [!TIP]
> 为什么要有清理时段：清理本身是 `unlink`（很快），但要先 `readdir + stat` 整个目录，上千张时在慢盘上能吃掉几百毫秒 —— 而生图高峰期恰恰是最频繁触发它的时刻。设成 `02:00–06:00` 就只在闲置时段扫。面板另外每 15 分钟看一眼表，夜里没人用也会按时清，不依赖有没有人生图。

### 清理日志：图没了，至少能查到是谁删的

自动清理是**默默发生**的：图打不开了，你分不清是被保留期清掉的、自己手滑删的，还是压根没生成成功。所以每次清理都会记一条：

| 列 | 含义 |
| --- | --- |
| 时间 | 本地时间 |
| 触发方式 | `自动清理` / `手动清理`（早于 N 天）/ `删除选中` |
| 删除 | 这次删了几张 |
| 释放 | 腾出多少空间 |
| 失败 | 有几张没删掉 |
| 参数 | 自动清理记「保留几天 · 什么时段」，手动清理记「早于几天」 |

- 存在 `~/.magpie-gptfree/cleanup-log.jsonl`（一行一条，0600），**只留最近 500 条**，设置页可以「清空日志」。
- 只记数量、释放空间和触发方式，**不记文件名、不记账号**——文件名是随机 hash，没有信息量。
- 没删到东西的清理（比如时段外跳过、本来就没有过期图）不记，避免日志被噪音淹掉。

### 生图错误日志：上游到底说了什么

生图失败时，面板上原来只有一个错误码（`upstream_text_reply` 这种），而上游返回的那句话在 worker → 网关 → 账本一路被丢掉了。账本每个号只留**最后一次**失败的原文，同一个号失败第二次就盖掉——真出问题时是一批号连着挂，事后根本翻不出来。

所以另存一份只追加的日志，每个账号失败记一条：

| 列 | 含义 |
| --- | --- |
| 时间 | 本地时间 |
| 账号 | 打码邮箱（悬停看槽位号 `s…`） |
| 错误码 | 中文标签，悬停有一句人话（限流 / 额度用尽 / 封号 / Token 失效 / 上游只回文字…） |
| 状态 | 上游返回的 HTTP 状态码 |
| 上游原文 | 上游那句话，去掉 token / 邮箱 / 链接后截断 240 字，悬停看全文 |

- 存在 `~/.magpie-gptfree/image-errors.jsonl`（一行一条，0600），**只留最近 500 条**，设置页可以「清空日志」。
- 只记失败，不记成功；账号只落槽位号，**不落邮箱明文**。
- 典型的用法：一批号同时报 `upstream_rate_limited`，点开原文看到 "You can try again later." → 等一会儿；看到 `upstream_banned` 配 "account has been suspended" → 这个号该换了。

日志里有两类行，看的时候别混：

| 行 | 意思 |
| --- | --- |
| **账号行**（显示遮罩邮箱） | 某一个号失败了一次。`状态` 列左边是我们返回给客户端的码，右边小字是上游**真实**返回的码——上游 200 + 一段文字时两者不一样（流是好的，只是内容不是图） |
| **整单行**（显示「整单 · 试 7/23」） | 一次客户端请求的汇总。`16 个号没轮到` 说明 55 秒预算在它们身上没来得及用——这跟「16 个号都失败了」是两回事 |

### 排查一次生图失败：两份日志对着看

插件这份是**按账号**记的（谁失败了、上游说了什么），Magpie 网关另有一份**按请求**记的日志：

```bash
docker logs magpie 2>&1 | grep 'gateway:' | tail -20
```

```
gateway: curl's call to gptfree-pool/gpt-image-2 on gptfree-pool failed:
  504 after 55.084s: gptfree-pool: 504 Gateway Timeout: 生图超时：55 秒内没有账号完成生成…
```

它只打**失败**的请求，一次请求一行，带客户端最终收到的状态码和总耗时——但看不到中间试了哪些号，那在插件的错误日志里。两份对着看才完整：网关说「55 秒超时」，插件说「试了 7 个号、16 个没轮到、每个都撞上上游回文字」。

## 常见问题

**Q：装完点「GPTFree号池」没反应？**
重启一次 Magpie 让它加载新插件，然后从顶部「插件」或左侧菜单进入。

**Q：需要自己装 Python 吗？**
不需要。插件首次运行会自动准备好运行环境；万一失败会明确报错，不会偷偷失败。

**Q：会动到我 Magpie 里原来的账号吗？**
不会。这是完全独立的临时号池，不碰你原有的配置。

**Q：为什么没有图片模型？**
号池里至少要有 1 个可用账号，图片模型才会出现在模型列表里。可用的图片模型有 `gpt-image-2`、`gpt-image-2.6`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`，其中 2.6 系列支持 GIF 动图输出。

**Q：账号会泄露吗？**
界面上只显示打码邮箱和槽位编号；密码、2FA、Token 只加密存在本机，不写进配置、不进网页、不进日志。

**Q：能不能只导入一个账号？**
可以。单人用也完全没问题，只是没有轮询和故障转移的额外好处。

**Q：图突然不见了，是被谁删的？**
去 **「设置」→「清理日志」** 看。自动清理、手动清理、删除选中各记一条，带时间、张数、释放空间和参数（保留几天、什么时段）。日志只留最近 500 条，也只记数量不记文件名。

**Q：生图一直失败，只知道一个错误码怎么办？**
去 **「设置」→「生图错误日志」** 看。每个账号失败都留一条，带上游返回的**原文**——到底是限流、额度用尽、封号还是 Token 失效，那句话通常说得比错误码清楚。

**Q：号池是空的时候，账号列表去哪了？**
空的时候总览页只留一张「号池里还没有账号」的引导卡，账号表、筛选、批量栏、失效分类都收起来了——导入第一个账号就会全部回来。

## 关于供应商页面（Providers）

- 在 **GPTFree号池** 导入账号后，插件会**自动把每个账号分别写进 Magpie 的供应商列表**，日常**不需要去「+ 添加供应商」**重复添加。
- 供应商页里出现 **GPTFree号池** 是正常的（所有认证类插件都会显示在那里），不是重复项。
- 在供应商页直接点 **GPTFree号池** 或「重新登录」，会**直接弹出系统文件选择框**：格式全对就直接批量入池；有格式错误行，会自动把文本预加载到左侧菜单「GPTFree号池」的可编辑文本框，让你改完再导。

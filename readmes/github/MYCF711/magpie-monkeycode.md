# MonkeyCode 与百智云 for magpie

把 **MonkeyCode 国内站 / 国际站 / 百智云** 三家接进 magpie：一个插件、三个供应商、各自的账号与计费互不覆盖。
国内站用你的**百智云账号**开通（同一份身份，两处通用），国际站与百智云各自独立。

```
3 家供应商 · 国内站与国际站各自独立登录态
国内 MonkeyCode 只走一条路：用你登录过的百智云账号开通（复用登录态，可选填邀请码）
百智云只留两条路：从本机客户端导入 / 浏览器登录（登录页上五种官方方式都行）
```

---

## 功能

- **三个供应商，账号各自独立** —— `monkeycode`（monkeycode-ai.com）、`monkeycodeintl`（monkeycode-ai.net）、`baizhi`（百智云）各自登录态、各自计费，互不覆盖。国内站与百智云是"一份身份两处通用"，但两家的账号与余额仍是两套
- **登录面按站点收敛** —— 国内站统一走百智云 SSO 复用凭证；百智云只保留「从本机客户端导入」和「浏览器登录」；国际版保留它自己的四条入口（见下「登录」）
- **百智云登录即自动开通国内站** —— 本机导入或浏览器登录成功后，后台用同一份会话开通国内站账号并写进 magpie；
  不阻塞百智云登录，失败也不影响它（自动开通是顺手做的事）
- **网关请求签名** —— MonkeyCode 的网关要求每个请求带 `X-OhMyAgent-Signature`；插件改过请求体（补 system、钳 max_tokens）之后会重新算签名
- **额度与积分如实显示** —— 每日额度（计费 token）、订阅档位（Basic / Pro / Ultra）、积分余额各一条读数；查不到的显示未知，不编造
- **额度用完后默认走积分** —— 官方前端的账号级开关「额度耗尽后消耗积分」默认是开的；插件在目录里把两种计费方式标清楚（见「模型」）
- **每日签到** —— MonkeyCode 两站支持：自动解开厂商的 PoW 验证题后签到，今天签过就不发写请求
- **多账号按序兜底** —— 勾几个账号就排几个号，前一个额度用完自动换下一个
- **模型目录跟随平台** —— 登录后跟随平台上下架；接口抖动时退回上次快照，不会把列表清空

## 登录

每个供应商只列**它真的有**的入口（`magpie plugin list` 里能看到的也正好是这些）：

| 供应商 | 登录入口 | 说明 |
|---|---|---|
| `monkeycode`（国内站） | **用百智云账号开通**（唯一一条） | 平时不用点：百智云登录成功就会自动开通。这条入口留给"补开 / 恢复" |
| `monkeycodeintl`（国际版） | API Key / 账号密码 / 从本机客户端导入 / 浏览器登录 | 国际站自己的入口，**不接**百智云、**不接**邀请码 |
| `baizhi`（百智云） | 从本机客户端导入 / 浏览器登录 | 浏览器里自己挑登录方式，插件不替你点；登录成功后会自动开通国内站 |

### 国内站：跟着百智云自动开通

**在「百智云 BaiZhiCloud」卡片上登录（本机导入或浏览器登录）成功后，插件会自动把国内站账号开出来**
——用同一份会话走一次平台 SSO，然后写进 magpie 的账号库。不需要你再去点第二次。

- **不阻塞登录**：一次 SSO 要 5~90 秒（要起一次无头浏览器），所以它在后台跑；百智云的登录结果**当场**返回，
  自动开通失败了也只少一张国内站卡，**百智云照旧登录成功**（失败原因会记一行日志）。
- **同一个身份不会变成两张卡**：按上游账号 id 原位更新；新的身份落到确定性键（`monkeycode#<sha8>`），
  重复登录天然幂等。
- **写完会回读**：宿主写记录时会"回成功但不落盘"，所以插件写完再读一遍对账；对不上就当没写成。
- **两种情况一律不写**：账号库读不出来（写了会把你的其它账号挤掉）、或拿不到账号身份（会变成"每登一次多一张卡"）。
- **不做启动扫库**：插件启动时**不会**替你补开历史账号 —— 那等于每次开机都起浏览器，还可能在你不期待的时候用掉邀请码。

### 国内站：手动「用百智云账号开通」（补开 / 恢复用）

这条入口保留着，用于**上线前就已经登录过的百智云账号**补开，或自动开通失败后重试。点一次，插件按这个顺序
找**已有的**百智云登录态，前面能用就不往后走：

1. **magpie 里已登录的百智云账号**（还有没开通国内站的）→ 完全不开窗口，一次开通一个账号
2. **本机桌面客户端里的百智云登录态** → 不开窗口
3. **本机持久登录态**（上一次从这个入口开窗登录时留下的）→ 静默复用，不弹窗
4. 以上都没有 → 打开百智云控制台让你登一次；这份登录态会留在本机，下次直接复用

开通出来的就是**你那个百智云账号对应的 MonkeyCode 账号**（首次开通时由平台自动建号）。
同一个账号再点一次只会更新凭据，不会变成两张卡 —— magpie 按上游账号 id 去重。
这一格上也有**一个**可选邀请码（国内站的 `inviter_id`），见下「邀请码」。

### 百智云：本机导入 / 浏览器登录

- **从本机客户端导入**：装过 MonkeyCode 桌面版并登录过百智云 → 一两秒就好，不弹任何窗口
- **浏览器登录**：在打开的窗口里自己挑 —— **微信扫码 / 支付宝 / 抖音 / GitHub / 观猹**（外加账号密码）；
  插件只做一件事：等你登完，读会话、换网关 Key。**它不会替你点任何一种方式**
- 窗口里读到会话**不算**登录完成：插件会真的去换一次 Key，换不到就继续等（窗口一开就有匿名会话）
- **登录成功就会自动开通国内站**（见上一节）。浏览器登录会依次问你**两格可选邀请码**：
  百智云的 `invite_code`、国内站的 `inviter_id`；「从本机客户端导入」没有输入框，它沿用**已保存**的
  国内站邀请码（自动开通会用到它）

### 国际版：四条入口原样

`API Key` / `账号密码登录` / `从本机客户端导入` / `浏览器登录`。

> 国际站**不认**百智云 SSO：它的登录入口是它自己的（GitHub / Google / 账号密码），
> `GET /api/v1/users/login` 302 到它自己的授权页、不经过百智云。所以国际站上没有「用百智云账号开通」，
> 留了也只会让用户对着一个必然超时的流程等几分钟。

### 老凭据照样能用

登录入口收敛**不影响**已经落盘的账号：国内站与百智云过去用 API Key 存的
`{type:"api", key}` 记录，插件仍然照旧解析（`{"access_token":…,"signing_secret":…}`、
`oma_…:密钥`、裸 token 三种写法都认），推理不受影响。想重新登录时走上面那张表里对应的入口即可。

## 邀请源（顶部开关，不是新按钮）

百智云与国内站各有一个 **`invite_preferred`「首选账号作为邀请源」** 开关，位置在账号下方（`placement: top`）。
国际站没有这个开关。

**关闭（默认）：自动滚动邀请**

- 百智云那一路用**最新注册账号自己的 8 位邀请码**（`GET /api/v1/user/invite-code` 的
  `data.invite_code`，8 位字母数字）—— **不是** user id。取不到就**不带**，登录照常。
- 如果最新那个账号还没有对应的国内站账号，国内站的 `inviter_id` 会**向前找最近一个能唯一精确匹配的已开通账号**，
  不漏掉猴站邀请；百智云那一路仍然是最新账号，不会被替换。
- 有账号时**什么都不问**，登录直接走。

**开启：首选账号作为邀请源**

- 登录时给一个**顶部选择框**：最新账号（自动）/ 各账号 / 手动输入邀请码，选完会记住。
- 首选模式**严格**使用你选的账号；映射不到国内站账号就**空着**，不会偷偷换成别的号。
- 选「手动输入邀请码」才出现原来的文本输入框：百智云「浏览器登录」两格（`invite_code` → `inviter_id`），
  国内站「用百智云账号开通」一格（`inviter_id`）。

**首次使用（还没有任何百智云账号）**

- 两站各自手动输入兜底：百智云的 `invite_code` 与国内站的 `inviter_id` **分别独立**，缺一路不清空另一路。

规则与边界：

- **两套码互不相通**，分别存在 `~/.cache/magpie/baizhi-invite.json` / `~/.cache/magpie/monkeycode-invite.json`；
  首选账号的选择另存 `~/.cache/magpie/baizhi-invite-source.json`。
- **只在首次注册 / 首次开通那一刻生效**，事后补不了；**自己邀请自己会被跳过**。
- 留空 / 填 `0` / 填 `1` = 沿用上一次的码；填别的 = 换成新码并记住。
- **国际版不参与**：这个开关、选择框与文本输入在国际站上都不存在。

## 模型

**DeepSeek / GLM / Kimi / Qwen / MiniMax** —— 登录后跟随平台目录上下架；目录还没拉到时用内置快照兜底，不写死模型数量。

卡片上的模型名带一个后缀，直接告诉你**这条按什么计费**：

| 后缀 | 含义 | 上游 id 形态 |
|---|---|---|
| `· 每日额度` | 走订阅档位的每日 token 额度（basic / pro / ultra 三档按权限放开） | `monkeycode-basic/…`、`monkeycode-pro/…`、`monkeycode-ultra/…` |
| `· 积分` | 直接扣积分 | 不带前缀 |

- **每日额度用完之后，还是这条模型继续扣积分** —— 不会"跳到另一条模型"上。后缀只说明这条模型**主要**走哪种计费，
  账号级开关「额度耗尽后消耗积分」默认就是开的（可在网页控制台关掉）
- **每日额度与积分是同一个账号的两条读数**，不是三个独立额度池：三档的差别是**能调哪些模型**，额度只有一个当日读数
- **积分孪生默认隐藏**：同一个模型如果既有档位条目又有积分条目，列表里只留档位那条（它额度用完会自动转积分，能力是超集）。
  怀疑两档其实不是同一权重时，设 `MAGPIE_MONKEYCODE_SHOW_CREDIT_TWINS=1` 让两条都出来
- **上下文窗口只声明有实测证据的**：DeepSeek 系 1,048,576（服务端 400 原文）；没证据的（如 `glm-5`）不声明 ——
  这个字段会被 agent 拿去算压缩阈值，谎报比缺一条更糟
- 思考档位不编：厂商没有下发「每个模型支持哪些思考档位」的元数据，插件就不声明

### 两个环境变量（调目录用的，平时不用设）

| 变量 | 作用 | 什么时候用 |
|---|---|---|
| `MAGPIE_MONKEYCODE_CACHE_DIR` | 模型目录缓存的**目录**（文件名固定为 `monkeycode-models-<provider>.json`）。默认 `~/.cache/magpie` | 单测要隔离开发机上的真实缓存；或者你有多套 magpie 配置想分开 |
| `MAGPIE_MONKEYCODE_CONTEXT_FLOOR` | 上下文窗口的**下限**（只抬不压）：平台自己报的 `context_limit` 是软配置（2026-11-04 实测标 200K、实际 240K/500K 的请求都是 200），所以插件直接按 1,048,576 报；设这个值可以把下限继续抬高 | 想让 agent 更晚才压缩历史时；设小了没有效果（不会压到 1M 以下） |


| 供应商 | 代表模型 | 备注 |
|---|---|---|
| `monkeycode` | `DeepSeek-Flash · 每日额度` / `GLM-5.3-Flash · 每日额度` | 档位条目按订阅权限放开；basic 调 pro/ultra 前缀会被上游 403 |
| `monkeycode` | `DeepSeek-Flash · 积分` / `GLM-5 · 积分` | 按积分计费；有档位孪生的会被隐藏 |
| `baizhi` | `deepseek-v4-pro`、`deepseek-v4-flash` | 按量扣积分，1,048,576 上下文 |
| `baizhi` | `glm-5` / `kimi-k2.6` / `qwen3.5-plus` 等 | 未知能力的模型照常列出，但不声明窗口 / 图片 |

> 只列各家的最新与热门。模型目录随时上下架，全表抄进 README 一个月就过期；
> 装好以后 `magpie plugin list` 拿到的才是真实的全部。

## 签到

**三个供应商都有每日签到**，由 magpie 按账号自动调用，不需要手动点：

- **MonkeyCode 两站**：解开厂商的 PoW 验证题后自动完成。
- **百智云**：对应控制台的「每日领积分 +100」。插件先读钱包的 `daily_temporary_credit_claimed`，
  已领取就**一个写请求都不发**；未领取才解同一套 PoW 验证题并 `POST /api/v1/user/wallet/daily-temporary-credit`。
  到账金额只认领取前后「每日积分」的正差额，不硬编码 100。

幂等：今天领过就只读一次钱包；并发调用按账号单飞，不会重复领取。签到失败不影响推理 ——
额度照常可用，只是当天没拿到奖励。百智云每日积分仍在**北京时间零点**过期。

## 安装

npm 上目前没有 `magpie-monkeycode` 包，GitHub 仓库也未配置 `magpie-plugin` topic，**发现**页搜索安装不可用。当前公开安装走仓库：

```bash
magpie plugin add github:MYCF711/magpie-monkeycode
```

装好后按你要用的供应商选一条路：

- **百智云**：**从本机客户端导入**（最快，不弹窗）或**浏览器登录**（微信 / 支付宝 / 抖音 / GitHub / 观猹 / 账号密码）。
  登录成功就**自动**开出国内站账号，不用再点第二次
- **国内站**：通常什么都不用做。只有两种情况需要点「用百智云账号开通」：① 这个百智云账号是插件**装好之前**就登录过的（不会自动补开）；
  ② 自动开通失败、想重试一次
- **国际版**：四条任选。已经拿到网关密钥 → 点 `API Key`，粘 `{"access_token":"oma_…","signing_secret":"…"}`（也接受 `oma_…:密钥` 一行）

想加第二个账号：在百智云卡片上再登录一个账号（每次都是干净窗口，不会读到上一个号的登录态），国内站会跟着自动开出第二个；
没自动开出来的，用国内站那条手动入口补一次（一次开一个）。

## 常见问题

**国内站为什么没有 API Key / 账号密码登录了？** 国内站统一通过百智云 SSO 复用凭证，所以只保留一条入口。
以前用 API Key 存下来的账号**不会失效**（见「老凭据照样能用」）；要换号就在百智云那张卡上换个号，国内站会跟着自动开通。

**百智云登录成功了，国内站卡片却没出现？** 自动开通是后台跑的，可能还在路上（一次 SSO 要几十秒），刷新一次列表看看；
仍然没有就点国内站那张卡的「用百智云账号开通」手动补一次 —— 它在百智云卡片上登录过的账号里挨个找，一次开一个。
自动开通失败不会影响百智云本身，失败原因会记一行日志。

**自动开通用的是哪个邀请码？** 用**已保存的国内站邀请码**（`monkeycode-invite.json`）。浏览器登录时可以在第 2 格填/换它；
「从本机客户端导入」没有输入框，所以沿用它。百智云自己那格 `invite_code` 只影响百智云账号的注册，两者不会混用。

**点了「用百智云账号开通」却提示已经有这个账号？** magpie 按上游账号 id 去重：同一个百智云账号只能对应一个国内站账号，
再开通只会更新凭据。要加新号，先在百智云卡片上换一个账号登录，再点开通。

**邀请码填了没生效？** ① 它只在**首次注册 / 首次开通**那一刻生效，事后补不上；② 两套码不通用 ——
百智云的码填第 1 格，国内站要填的是 MonkeyCode 的邀请人 id（第 2 格）；③ 国际版不接邀请码；
④ 「从本机客户端导入」用的是**已保存**的国内站码，想换码要先在浏览器登录那两格里填一次。

**「从本机客户端导入」说没读到登录态？** 桌面版要**先登录成功**才会把会话写到本机。打开桌面版登一次，再回来点。
桌面版的服务器是**国内站 / 国际站二选一**的，插件只认本站那份 —— 装的是另一站时代码会说「桌面客户端登录的是另一个站点」，
切换过去重登一次即可。

**国际版点网页登录，界面报「已登录，但 magpie 无法列出它」？** 0.2.36 已修。根因不在国际站：magpie 的插件宿主只在登录结果带
`refresh` 字段时才把 oauth 登录写进 `plugin-auth.json`，缺这一格时界面照旧显示成功、账号却没落盘。升级后重登一次即可。

**为什么模型列表里少了一条「· 积分」的？** 它和某个「· 每日额度」条目是同一个模型，默认只留档位那条。
想两条都看：设环境变量 `MAGPIE_MONKEYCODE_SHOW_CREDIT_TWINS=1` 再刷新。

**为什么看不到 pro / ultra 档的模型？** 这些模型需要对应订阅。插件按账号当前档位过滤目录，basic 账号不会看到没有权限的 pro / ultra 条目；这不是列表坏了，也不存在一个叫「已锁定」的标记。

**额度条显示「剩余额度未知」？** 平台接口暂时读不到（网络抖动或未登录态查额度）。推理不受影响，下一轮刷新会恢复。

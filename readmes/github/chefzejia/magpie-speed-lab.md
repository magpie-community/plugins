# Magpie Speed & Effort Lab (`magpie-speed-lab`)

> **“为什么有时候快、有时候慢？现在该选哪个渠道、模型和思考档位？”**
> 一键拆解首字等待、隐藏思考与真实吐字速率，结合历史账单与并发实测，直接算出最适合你的模型与档位排行榜。

---

## 核心特性（零配置 · 动态端口自适应）

- **🔌 100% 零配置，操作系统动态分配空闲端口（无端口冲突、无填写项）**：
  插件启动时自动向操作系统申请空闲回环端口（`127.0.0.1:0`），并通过原子会话文件（`page/session.js`）与 Magpie 侧边栏沙箱页面自动握手跳转。无需填写任何端口号，彻底杜绝多实例或固定端口冲突。
- **🏆 场景化四维加权选型排行榜（用数据决定该用哪个）**：
  支持 **多轮 Agent 工具协同 / 交互问答与长代码 / 复杂推理与边界攻坚 / 高频批处理与性价比** 四大预设及实时权重滑块，对所有 `[Provider × 模型 × 推理强度]` 进行 `0–100` 综合打分排序。
- **🔍 慢请求五大物理元凶自动归因 + 消失的工具流 `tok/s` 还原**：
  零成本解析 `usage.jsonl`，利用底层 `flow_ms` 找回加密思考纯工具调用轮次的真实流速，并自动量化慢请求到底慢在「上下文膨胀 ≥120K」、「深度思考长尾」、「缓存未命中」还是「上游重试/本地脱敏」。
- **⚡ 多推理档位（Effort）实时并发流式赛马**：
  内置标准代码流探针与双隐藏漏洞推理探针，12 秒并发实测 `low / medium / high / xhigh` 各档位的真实 TTFT、思考开销与边界检出率。

## 一、 第一性原理：物理阶段解耦与加权选型模型

### 1. 单轮端到端耗时的四阶段物理方程

任何一次经过网关的大模型调用，其挂钟时间（Wall-Clock Time）严格由四个正交阶段相加构成：

$$T_{\text{turn}} = \underbrace{T_{\text{gateway}}}_{\text{本地网关与脱敏}} + \underbrace{T_{\text{prefill}}\big(L_{\text{ctx}}, R_{\text{cache}}\big)}_{\text{网络排队 + 上下文预填充}} + \underbrace{T_{\text{think}}\big(E_{\text{effort}}\big)}_{\text{隐藏/可见思维链生成}} + \underbrace{\frac{N_{\text{out}}}{V_{\text{decode}}}}_{\text{流式 Token 解码传输}}$$

而在多轮 Agent 工具循环中，完成一个任务的总耗时为 $T_{\text{task}} = \sum_{i=1}^{N_{\text{turns}}} \big(T_{\text{turn}, i} + T_{\text{tool}, i}\big)$。由于单步工具调用的输出 $N_{\text{out}}$ 通常极短（100~250 tokens），**前向等待（$\text{TTFT} = T_{\text{gateway}} + T_{\text{prefill}} + T_{\text{think}}$）占到了总耗时的 70% 以上**；相反，在长文/长代码单轮交互中，流式吞吐率 $V_{\text{decode}}$ 才成为主导体感的核心变量。

### 2. 四维物理指标与工作负载加权排行榜

脱离工作负载谈“谁最快”是伪命题。本实验室对每一个候选 `[Provider × Model × Effort]` 在四个正交物理维度上进行 `0–100` 归一化评分：

| 评价维度 | 物理定义与计算依据 | 核心衡量目标 |
| :--- | :--- | :--- |
| **⚡ 首响敏捷度 (`Responsiveness`)** | 基于首动作延迟 `TTFT P50` 的指数衰减映射 | 决定多轮 Agent 每一步工具调用的起步等待体感 |
| **🚀 流式吞吐率 (`Throughput`)** | 基于剔除首尾突发缓冲、利用底层 `flow_ms`（中间 80% 字节流）还原的 `Decode tok/s` | 决定长代码、长方案生成时的持续输出流畅度 |
| **🛡️ 长尾稳定性 (`Stability`)** | 基于 `P90 / P50` 抖动比值、P90 绝对耗时上限与慢请求发生率 | 衡量上游渠道账号池拥堵与极端深度思考卡顿风险 |
| **🎯 推理效能比 (`Efficiency`)** | 基于前缀缓存命中率（`Cache Hit %`）、思考 Token 经济性与探针边界检出质量 | 衡量“思考耗时是否转化为有效准确率”及缓存成本控制 |

内置 **4 类典型工作负载预设权重**（界面支持拖动滑块实时自定义权重并0延迟重排总榜）：
- **🤖 多轮 Agent 工具协同 (`agent_loop`)**：首响敏捷度 `45%` · 长尾稳定性 `25%` · 流式吞吐 `15%` · 推理效能 `15%`
- **💬 交互问答与长代码 (`interactive_chat`)**：流式吞吐 `45%` · 首响敏捷度 `25%` · 长尾稳定性 `15%` · 推理效能 `15%`
- **🧠 复杂推理与边界攻坚 (`deep_reasoning`)**：推理效能与质量 `40%` · 长尾稳定性 `30%` · 首响敏捷度 `15%` · 流式吞吐 `15%`
- **⚡ 高频批处理与性价比 (`cost_efficiency`)**：推理效能与缓存 `35%` · 流式吞吐 `30%` · 首响敏捷度 `20%` · 长尾稳定性 `15%`

## 二、 双引擎架构（被动真实工况遥测 + 主动受控并发探针）

1. **🏆 引擎一：真实工况加权排行与归因遥测（被动分析 · 0 成本 · 秒开）**
   - 直接流式解析 `~/.config/magpie/usage.jsonl`，无需额外消耗 Token，基于你的真实生产请求生成**场景化加权排行榜（含前三名领奖台与 S/A/B/C 评级）**；
   - **找回纯工具调用轮次的流式速率**：当模型在 `/v1/responses` 协议下完成加密思考并直接发起 Tool Call（无正文 `first_text_ms`）时，利用底层 `flow_ms` 还原真实传输速率；
   - **慢请求五大物理元凶归因雷达**：自动对慢调用（`≥18s` 或 `TTFT ≥13s`）进行根因切片（深度思考长尾、120K+ 上下文膨胀、Prompt Cache 冷启动未命中、上游报错重试/排队、本地 PII 脱敏开销）；
   - **跨档位边际收益自动预警**：自动识别同一模型在极高推理档位（如 `xhigh / max`）相比中坚档位（`high / medium`）是否存在严重的耗时膨胀与边际收益递减。

2. **⚡ 引擎二：多档位并发流式基准探针（主动压测 · 10~15 秒出榜）**
   - 当需要横向评测新接入的 Provider 或对比不同 `effort` 档位在当前时刻的通道表现时，并发发送标准化流式载荷（`code_stream` 确定性代码生成探针 / `bug_reasoning` 双隐藏漏洞边界诊断探针）；
   - 原生支持 `/v1/responses`（携带 `reasoning: { effort }`）与 `/v1/chat/completions`（携带 `reasoning_effort`），实时赛马结束后自动按照当前工作负载权重产出实测排行榜。

## 三、 安装与使用

### 1. 在 Magpie 中安装（推荐）

在 Magpie 的 **「插件 › 发现」** 页面直接搜索 `magpie-speed-lab` 点击安装，或在底部「已有想装的？」输入框 / 终端执行：

```bash
magpie plugin add github:leozejia/magpie-speed-lab
```

安装后：
- 在 **Magpie 桌面端或 Web 窗口** 左侧边栏点击 **「测速与选型排行」** 即可直接打开交互式加权排行榜看板（自动发现动态端口，无需任何配置）。

### 2. 终端 CLI 排行榜速查

```bash
# 1. 查看真实工况下的加权选型排行榜（默认：多轮 Agent 工具协同场景）
node cli.mjs report 7d

# 按不同工作负载场景输出加权排行榜
node cli.mjs report 7d --profile=interactive_chat
node cli.mjs report 7d --profile=deep_reasoning
node cli.mjs report 7d --profile=cost_efficiency

# 2. 发起主力推理模型多档位并发流式探针并输出实测排行榜
node cli.mjs probe
node cli.mjs probe --bug
```

### 3. 运行单元测试

```bash
npm test
```

# Magpie Auto Retry

Magpie 提供商临时出故障时，替 Agent 等一等、再试一次。默认不限制重试次数；请求成功后，结果交回 Agent，任务继续往下走。

[English](README.en.md) · [Magpie 插件文档](https://usemagpie.ai/docs/zh/plugins) · [技术架构](docs/architecture.md) · [管理 API](docs/api.md)

## 先看风险

**持续重试可能产生额外费用，也可能触发提供商的限流、风控，甚至封号。** 请求失败不代表提供商没有计费。插件不保证账号安全，也不解决账号封禁、密钥失效或余额不足。

持续限流时，可以加长等待时间、降低并发，或者关闭自动重试。没有一组参数能保证不被封号。

## 安装和更新

```sh
magpie plugin add github:koala9527/magpie-auto-retry
```

在 Magpie 的插件列表里启用 **自动重试**。已安装的用户使用插件更新入口更新，并重启插件。当前修订版是 **1.0.2**，更新已有安装不会重置保存的设置。

命令行也可运行 `magpie plugin update`（更新全部社区插件），再重启本插件。

### 默认本地转发

插件启动时会自动检测 Magpie 管理的本机 Codex 配置，将原网关地址（默认 3425）自动配置转发至重试插件端口（`http://127.0.0.1:3430/v1`）。如果 Codex 已经在运行，只需**重启一次 Codex** 即可直接走重试服务，无需手动修改配置文件。页面也不显示冗余的“接入方式”标签页，可在“运行信息”栏直接查看转发配置状态。

如果是外部或自定义客户端，可将 API 基址指向 `http://127.0.0.1:3430/v1`，模型名与 Magpie key 保持不变。

## 它怎么工作

可以把它理解为 Magpie 门口的一个转接服务。它不替模型回答，也不重新启动 Agent，只负责把**还没结束的请求**等到有结果。

```text
Agent → 重试服务 :3430 → Magpie :3425 → 提供商
```

1. Agent 发来请求，插件先交给本机 Magpie，再由 Magpie 调用提供商。
2. 遇到临时故障，如网络断开、408/425/429/5xx，插件等一会儿再发送同一个请求。Agent 的原连接保持着，不需要再发一遍。
3. 连续失败时，等待逐次加长。默认参数、关闭抖动后的例子是 **2 → 4 → 8 → 16 → 32 → 60 → 60…秒**。实际默认开启抖动，时间会有小幅变化。
4. 请求完整成功后，把结果交回 Agent，由 Agent 继续任务。
5. **永久错误与风控拦截立即终止，不盲目重试**：
   - **内容安全过滤（`content_filter` / 敏感拦截）**：触发提供商的内容审核或安全风控时，立即终止并返回错误。对违规提示词反复重试不仅不会成功，还会连续触发上游风控规则，极大增加封号风险。
   - **协议不匹配（如 `requires Responses for tool calls`）**：当前账号或模型协议不支持所请求的功能，重试无法解决，直接返回客户端。
   - **鉴权与额度错误**：401/403、无效请求/模型、明确的余额不足、密钥或证书错误，立即交回客户端。

### “无限重试”也有结束的时候

- 已经发出**文本、思考内容或工具调用**后，不从头重试。后面断流会按原协议报告错误并结束，避免重复输出或执行。
- 输出前遇到空流、流内临时错误或断流，可以继续重试。
- 取消、断开连接、Agent 退出、插件停止或重启都会结束请求。未完成请求不存盘，重启后不会复活任务。
- 非流式客户端如果有自己的 HTTP 总超时，仍可能先结束等待。插件不会取消客户端的超时设置。
- 等待“心跳”只是流式连接上的注释，不是新模型请求，也不是检测提供商是否可用。

## 参数怎么设

页面的 **运行设置** 点击 **保存设置** 才生效。保存不会重新开始当前请求，后续尝试会读取新设置；关闭重试会结束正在等待重试的请求。**恢复默认** 只回填表单，还要保存。

页面时间单位是秒；API 字段以 `Ms` 结尾的时间单位是毫秒。第一次使用可以先保持默认；持续限流时先调长等待、调低并发，不要靠更快重试硬顶。

| 页面设置 / API 字段 | 默认值；范围 | 通俗说明 |
| --- | --- | --- |
| 启用自动重试 / `enabled` | 开启 | 临时失败后继续尝试。关闭后新请求只尝试一次，已在等待重试的请求也会停止。 |
| 初始退避 / `initialDelayMs` | 2 秒；0.1–60 秒 | 第一次失败后等多久再试。太短会更频繁地请求提供商。 |
| 最大退避 / `maxDelayMs` | 60 秒；0.1–3600 秒 | 普通重试每次最多等多久，不能小于初始退避。**不是累计等待上限**；到这个值后仍重试。提供商的 `Retry-After` 可以要求更久，最长接受 24 小时。 |
| 退避抖动 / `jitter` | 开启 | 等待上下随机浮动约 25%，不超过最大退避，避免多个请求一起重试。不是切换模型或账号。 |
| 单次请求超时 / `attemptTimeoutMs` | 120 秒；1–600 秒 | 一次尝试等待响应头，以及读完非流式回复的上限。不是整个任务时限；流式响应开始后改用流空闲超时。 |
| 流空闲超时 / `streamIdleTimeoutMs` | 120 秒；1–600 秒 | 上游流多久没新数据就算中断。收到数据会重新计时；已输出内容后不重放。 |
| 等待心跳 / `heartbeatMs` | 10 秒；1–30 秒 | 隔多久给流式客户端发一条“仍在等待”的注释，不混进回答，不额外调用模型。 |
| 最大并发请求 / `maxConcurrentRequests` | 32 个；1–256 个 | 同时接待多少请求。推理、请求上传阶段和模型列表共用名额；满了返回 429，不排无限长的队。不是重试次数。 |
| 历史保留天数 / `historyDays` | 30 天；1–90 天 | 保留统计和故障记录多久，不是保留聊天记录。 |
| 本机 Magpie 上游地址 / `upstreamUrl` | `http://127.0.0.1:3425` | 插件往哪里转发。填本机 Magpie 地址，不是提供商网址，也不是插件自己的 3430 端口。 |

插件监听端口默认 **3430**，与上游 **3425** 是两回事。换监听端口时，在 Magpie 插件选项中修改后重启，并同步修改 Agent 地址：

```sh
magpie plugin options magpie-auto-retry '{"port":3430,"upstreamUrl":"http://127.0.0.1:3425"}'
```

这里的 `upstreamUrl` 用于首次初始化；已有安装以页面保存的设置为准。

## 页面统计怎么看

- **故障尝试**：一次上游调用失败就加一。同一个请求失败十次再成功，是十次故障，不是十个任务失败。
- **恢复请求**：至少失败过一次，最后完整成功的请求数。
- **观测可用时长 / 可用率**：成功后的有效区间算可用，失败后的有效区间算故障；连续 5 分钟没流量或服务离线的时间算未知。
- 可用率 = 可用时长 ÷（可用时长 + 故障时长）。没观测时显示 `—`，不是 100%。这不是提供商全天可用率承诺，也不是剩余额度。
- Magpie 内部可能试过多个路由成员，页面只统计插件实际收到的结果，不猜测内部失败次数。
- 当前请求可以手动取消；导出 JSON 只含统计，Magpie 内可全选复制，独立浏览器还可下载。

## 支持哪些请求

支持 OpenAI Chat Completions、Responses、Anthropic Messages 和 Gemini 的 `generateContent` / `streamGenerateContent`；也转发 `GET /v1/models`。文件上传/删除和工具执行接口不走这个重试服务。

通过 Magpie 安装时，配套中间件传递实际响应提供商的 id/name，标记在返回 Agent 前移除。独立运行时按请求模型归属统计，路由组名不代表真实提供商。

## 数据存在哪

插件模式：Magpie 配置目录下的 `magpie-auto-retry/`。独立模式：`~/.magpie-auto-retry/`，可用 `--data-dir` 指定。

- `settings.json` 保存设置，`statistics.json` 保存提供商名称、聚合计数、小时记录、故障区间和最近 200 条事件。
- 请求和认证头只在内存中转发；提示词、聊天、工具参数和密钥不写入统计、日志或导出。
- 服务只监听本机，管理接口使用启动时生成的令牌并校验 Host/Origin。没有遥测、外部字体或 CDN。
- 状态文件损坏时保留 `.corrupt-<时间>` 副本。写盘失败会在页面显示，不假装已保存成功。

## 开发和验证

独立开发需要 Node.js 22+；插件模式使用 Magpie 管理的 Bun，不用另装 Node。零运行时依赖，页面是原生 HTML/CSS/JS。

```sh
git clone https://github.com/koala9527/magpie-auto-retry.git
cd magpie-auto-retry
npm ci --ignore-scripts
npm run dev
# 浏览器打开 http://127.0.0.1:3430/
```

```sh
node bin/magpie-auto-retry.mjs --port 3430 --upstream http://127.0.0.1:3425 --data-dir .local/state
npm run check
npm test
npm run test:coverage
npx playwright install chromium
npm run test:browser
npm pack
```

测试覆盖真实 HTTP/SSE 恢复、1001 次失败、取消、运行中关闭重试、不重放工具调用、存储及浏览器交互。见 [验证记录](docs/verification-1.0.2.md)、[质量标准](CONSTRAINTS.md) 和 [贡献说明](CONTRIBUTING.md)。

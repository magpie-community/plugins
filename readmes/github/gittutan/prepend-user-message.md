# Append user message

Magpie 网关中间件：跳过已识别的客户端上下文，在第一条包含用户输入的消息文本末尾追加界面配置的内容。直接修改同一条消息，不新增消息，系统消息和其他消息保持原样。追加内容使用 Markdown，不添加标题或插件标签。

## 使用

1. 在 Magpie 的 **Plugins** 页面点击 **Add a plugin**，填写 `github:gittutan/prepend-user-message`。若终端已有 `magpie` 命令，也可运行：

   ```bash
   magpie plugin add github:gittutan/prepend-user-message
   ```

2. 在 **Settings → Plugins** 中确认 **Gateway middleware** 已开启。
3. 在 **Plugins → Installed** 中找到本插件，点击 **Options**，填写并保存：

   ```json
   {
     "append": "请用中文回答，并给出具体操作步骤。"
   }
   ```

本地开发时，也可以在 **Add a plugin** 中填写包含 `package.json` 的目录绝对路径，或在该目录运行 `magpie plugin add ./`。没有 `magpie` 命令时，直接使用界面安装即可。

后续直接在此界面修改 `append`，无需编辑代码。`package.json` 中的 `magpie.options` 只提供编辑器初始内容，必须在 **Options** 中保存后才会作为运行配置。未配置、配置为非字符串、空字符串或纯空白文本时，不修改请求；清空配置不会清理历史追加文本。配置首尾空白会被去除，已包裹的最外层 `**` 不会重复添加。多段文本可在 JSON 字符串中用 `\n` 换行。

如已安装旧的单文件版本，请先在 **Plugins → Installed** 中移除旧条目，再安装目录版本。

支持以下用户输入格式：

- Chat / Anthropic：按顺序查找 `body.messages` 中包含用户输入的 `role: "user"` 消息。
- Responses（如 Codex）：纯字符串 `body.input`，或按顺序查找 `body.input` 数组中包含用户输入的 `role: "user"` 消息。
- 消息的 `content` 可以是字符串或内容块数组；数组形式只在最后一个可追加的 `text` / `input_text` 文本块中追加，保留上下文、图片等其他内容块。

定位用户输入时，跳过空白文本，以及以 `<environment_context>`、`<user_instructions>`、`<turn_aborted>`、`<user_shell_command>`、`<system-reminder>` 或 `# AGENTS.md instructions for …` 等 Markdown 指令文件标题开头的文本。这些标记按整段文本识别，不拆分同一文本块中的上下文和正文。

没有用户消息或可追加的文本时，原样返回请求。Gemini 的 `contents` 格式暂未支持。

## 修改配置与缓存

追加后的同一条用户消息形如：

```text
用户输入 **配置的追加内容**
```

追加前去除用户文本末尾的空白，再用一个空格连接 `**配置内容**`，不添加标题或额外换行。配置内容内部保持原样；包含空行、列表、代码等复杂 Markdown 时，整段包裹 `**` 不保证所有内容都渲染为粗体。

按以下顺序处理所选用户文本，命中后不再执行后续匹配：

1. 包含完整的 `**当前配置**`：立即返回，不修改消息，也不继续清理其他旧内容。
2. 包含完整的未加粗配置：从首次匹配位置替换到文本末尾。
3. 前两步均未命中：才提取并匹配配置前缀，从首次匹配位置替换到文本末尾。
4. 全部未命中：在文本末尾追加。

前缀取当前配置开头的第一句话或第一行，以先遇到的 `。！？!?`、英文句号加空白或文本结尾、换行为边界。保留句末标点，不包含换行；没有这些边界时，前缀等于完整配置，不重复搜索。

第 2、3 步最终写入的都是 `空格 + **当前完整配置**`，命中位置前紧邻的旧 `**` 也会一起替换。例如配置从 `请用中文回答。` 增加为 `请用中文回答。给出操作步骤。`：

```text
原消息：用户输入 请用中文回答。 **请用中文回答。**
处理后：用户输入 **请用中文回答。给出操作步骤。**
```

这个开头需要保持不变，且不要在需要保留的用户正文中使用同样的开头：首次命中后面的其他文字也会被替换。若改掉开头，或旧配置没有上述边界而新配置继续延长，可能无法识别旧内容。

第 1 步命中直接返回 `undefined`，不提取前缀、不截取和拼接消息文本，也不重新序列化请求体。

防止叠加不等于保持旧缓存：修改或移除追加段会改变该位置开始的文本及其 hash，可能影响前缀缓存。配置不变、请求中的原始历史不变时，生成的追加段保持一致。插件定位的是本次请求中的第一条实际用户文本，没有跨请求的会话存储；增量请求或历史压缩后，不保证仍定位到会话最初的消息。

完整历史的多轮请求只修改第一条实际用户消息，后续用户轮次不会各追加一份。首次将旧格式迁移为 Markdown 格式也会改变该位置的文本及其 hash。

## 排查未生效

确认插件已安装并启用，且 **Options** 中的 `append` 已保存为非空字符串。更新本地代码后，在 **Plugins** 中关闭再开启本插件，以重新加载代码。

追加发生在网关转发请求时，不会改写客户端显示的聊天记录。检查发往上游的请求中，用户消息文本的末尾是否包含配置内容；仅询问模型是否记得这些要求，不能可靠判断中间件是否生效。

Magpie 的“上下文窗口”按内容分类，不直接按 `role` 划分轮次：`instructions` 显示在“系统提示词”；以 `<environment_context>` 等标记开头的用户消息也会被归入该区块。旧版本若选中了这种消息，追加内容会随它显示在 `environment_context` 等条目中。当前版本跳过上述上下文标记，追加到用户输入后，预期在“对话”的对应轮次中查看。这只是界面分类，消息的 `role` 仍为 `user`。

中间件使用同步 JavaScript，无依赖，无需构建。

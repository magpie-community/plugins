# magpie-quota-glance

一个 magpie 插件：把每个供应商的积分使用详情和总览显示在底部板块，同时也标记了3天内过期的积分详情。

它在「用量 › 概览」底部加一块面板，按供应商汇总该供应商下**所有账号**的积分——积分总量、已用积分与消耗百分比、剩余积分，以及**最近 3 天内到期**的积分（带到期时刻）。同一个面板也会出现在每个供应商的编辑页里，只显示该供应商。

这是一个纯面板插件：不碰你的请求、不调用厂商接口、不从 magpie 读取任何数据（`magpie plugin` 显示 `reads nothing`）。

## 面板显示什么

| 行 | 含义 |
| --- | --- |
| 积分总量 / 令牌总量 | 该供应商下各账号数量窗口 `limit` 之和，**按单位分开**（积分一张卡、令牌一张卡） |
| 已用 / 消耗 | 窗口 `amount`（已用数量）之和，及其占总量比例 |
| 剩余 | 总量减已用 |
| 3 天内到期 | 批次在 72 小时内作废的额度（`runsOutAt`），以及 72 小时内重置的窗口 |

每个账号还会显示：套餐、已用 / 上限、消耗百分比、逐窗口进度条、重置时间、到期积分与时刻。

### 各家额度不是一个口径

各家的 `auth.usage` 报的额度形状并不统一，所以面板先归一化再显示，
**供应商本身永远不会因为口径不同而消失**：

| 口径 | 判定依据 | 显示 | 是否进合计 |
| --- | --- | --- | --- |
| 数量（amount） | 窗口有 `limit > 0` | 总量 / 已用 / 消耗% / 剩余 + 进度条 + 到期分档 | 是（按单位分开） |
| 百分比（percent） | 窗口只报 `used`（已用百分比）或 `remaining`（剩余百分比） | 「剩余 40%（令牌 · 本周令牌）」 | 否 |
| 余额（balance） | 窗口或条目有数值 `balance` | 「余额 1,200,000 令牌」 | 否 |
| 文案（text） | 只剩一句 `display` | 供应商给的那句话（例如「余额查询失败：…」） | 否 |

**单位不同不相加**：积分（credits）、令牌（tokens）、点数各算各的。合计区里
「积分总量」和「令牌总量」是两张卡片，谁也不会混进谁；
一家供应商同时给积分和令牌，卡片里就分成两组，各自带进度条和到期分档。

同义单位会归一（`credits` 与「积分」是同一个意思），否则面板上会出现两张
都叫「积分总量」的卡。

额度口径是四选一，但供应商可以同时出现多种（例如既有积分窗口又有余额钱包），
这种卡片标「混合口径」。不是金额口径的供应商不参与合计，顶部有一行
**「不计入合计」** 把余额、百分比、文案列出来，免得以为被吞了。

### 令牌额度

按令牌数量计的额度照样显示，而且不和积分混加。magpie 的窗口不一定带 `unit`，
所以插件这样认：

- 窗口带 `holds.tokens`（这一份额度按令牌算）→ 该供应商的窗口都按令牌计；
- `display` 里写着「671 / 24,072 积分」这种「已用 / 总量 + 单位」→ 单位取自文案；
- 都没有 → 按「额度」这个中性单位显示。

ZCode 就是这种：GLM-5.3 是 3,000,000 令牌、GLM-5.3-Flash 是 5,000,000 令牌，
两家额度池分开显示（`令牌·GLM-5.3`、`令牌·GLM-5.3-Flash`），
合计区是一张「令牌总量」卡。

### 新加的供应商为什么以前不显示

旧版只认「积分窗口」，于是下面这几种供应商会被整条丢掉：

- 额度是**预付费余额**的（如 500 点、10,836 积分）
- 额度只报**百分比**的
- 额度只有**一句文案**的（常见于读取失败）
- 刚加进来、magpie **还没读到额度**的（`quotas.json` 里根本没有它的条目）

现在有两处改动：

1. 窗口按上面四种口径归一化，只有拿不到任何数值的供应商才显示「待读取」；
2. 供应商清单不再只看 `quotas.json`，还会把 magpie 自己的供应商注册表
   （`plugin-providers.json`：插件声明的供应商；`providers.json`：自己加的供应商）
   合并进来。所以**刚加的供应商几秒内就会出现**，哪怕额度还没读到。

只统计总额窗口；带 `aside` 标记的（或 `spans[i].aside`）是同一笔积分的拆分
（例如「总积分」下面的「基础积分包」「赠送积分包」），跳过不重复计入。
额度一个都读不到的账号仍然留在卡片里（显示「额度不可读」），但不会把供应商从
面板上抹掉。

## 到期分档

每张供应商卡片标题右侧有五个色块，**越临期越靠左**：

| 色块 | 含义 |
| --- | --- |
| 1 天内（红） | 24 小时内作废的积分 |
| 3 天内（橙） | 1–3 天 |
| 7 天内（金） | 3–7 天 |
| 15 天内（绿） | 7–15 天 |
| 15 天以上（金） | 15 天以后才到期，或没有已知的更早到期日；金色渐变描边 + 外发光 |

五档相加 **恒等于该供应商的剩余积分**。

顶部还有一行全站合计的同款分档（「剩余按到期分布」），**默认收起**，点标题栏的 **「到期分布」** 展开，选择会记在插件 options 里。

五档色块是同一套样式：各自颜色的渐变描边缓慢绕圈 + 呼吸发光；每个色块还会不定时有一道高光**从右向左**扫过（周期与相位随机，所以不会整齐同步）；鼠标悬停时轻微上浮。系统开启「减少动态效果」（`prefers-reduced-motion`）时全部动画关闭；数值为 0 的档淡化显示且不参与动画。

口径说明：magpie 的 `auth.usage` 只给出「最快作废的那一批」的时刻（`runsOutAt`）与周期重置时刻（`resetsAt`），没有逐批到期明细，所以除那一批之外的剩余积分统一归入「15 天以上」，这样各档之和不会与剩余积分对不上。

## 只算你想算的供应商

- 右上角 **「选择供应商」**：列出当前识别到的所有供应商，勾选决定哪些纳入合计，支持「全选 / 全不选」。
- 每张供应商卡片右侧 **「排除」**：一键把该供应商去掉。
- 被排除的供应商不显示卡片，也不计入总量 / 已用 / 剩余 / 3 天内到期；表头会标明「已排除 N 个」。
- 选择保存在本插件自己的 options 里（`plugins.json` 中该插件条目的 `options.excluded`），重启、刷新都保留。

另外提供一个 MCP 工具 `quota_snapshot`（在 magpie 的 MCP 里显示为 `magpie-quota-glance_quota_snapshot`）：agent 可以直接问「现在还有多少积分、哪些快到期」，拿到的就是面板用的同一份快照 JSON。

## 安装

从本地目录（解压后）：

```bash
magpie plugin add "<该文件夹的绝对路径>"
magpie plugin            # 预期输出：panels  Credits on usage, Credits on provider (reads nothing)
```

或直接从 GitHub 拉：

```bash
magpie plugin add github:Black-Sky9/magpie-quota-glance
```

装好后打开「用量 › 概览」，滚到底部即是面板。详细步骤、卸载与排错见 [INSTALL.md](INSTALL.md)。

## 工作原理

magpie 的插件页面跑在沙盒里，只能读 `usage:summary` 与 `providers:list`，且 CSP 是
`connect-src 'none'`——所以页面拿不到按账号的额度。因此由插件宿主（Bun，`index.mjs`）
读额度数据，算好聚合快照后写入 `panel/live.js`；面板用沙盒允许的
`<script src="live.js?v=…">` 把它取回来。

```
/v1/magpie/quotas?all=1 ─┐
                          ├─► index.mjs（聚合）──► panel/live.js ──► 面板（每 3 秒）
~/.config/magpie/quotas.json ─┘
```

额度数据有两个来源，接口优先、缓存兜底：

- **实时接口** `http://127.0.0.1:<端口>/v1/magpie/quotas?all=1`（端口取自
  `gateway.json`，默认 3425）：magpie 自己算好的 `auth.usage` 结果。新鲜、带
  `remaining` 百分比、带 `holds.tokens`（令牌额度）、带余额文案；
  **ZCode 的令牌额度只在这里**，缓存里连它都没有。
- **缓存** `~/.config/magpie/quotas.json`：magpie 自己的缓存，接口拿不到时兜底；
  它还带 `aside` 标记，能指出哪些窗口是同一笔额度的拆分。

实时接口不带 `aside`，插件用「和关系」还原拆分：同一单位下，若最大窗口的上限
正好等于其余窗口上限之和，其余窗口就是它的拆分（CodeArts 的「总积分」下面挂着
「基础积分包」「赠送积分包」），只留最大的那个。两份额度不同的窗口
（ZCode 的 GLM-5.3 与 GLM-5.3-Flash）不满足这个关系，照样都留。

供应商清单来自 magpie 自己的注册表（`plugin-providers.json`：插件声明的供应商；
`providers.json`：用户自己加的供应商），和额度数据合并：
**刚加的供应商几秒内就会出现在面板上**，哪怕额度还没读到（显示「待读取」）。

聚合口径：

- 窗口先分口径：`limit > 0` 的是数量口径（带 `unit`：积分 / 令牌 / 积分 / 点 …）；
  有数值 `balance` 的是余额口径；只报 `used`（已用百分比）或 `remaining`（剩余百分比）
  的是百分比口径；标了 `text` 或只剩 `display` 的是文案口径。
- **按单位分组**：数量口径按「单位 + 窗口名」分组（同一家供应商的 GLM-5.3 与
  GLM-5.3-Flash 是两份额度），全站合计再按单位并成一张卡；同义单位归一
  （`credits` 与「积分」）。
- 只统计总额窗口；拆分窗口（缓存里的 `aside` 标记，或实时接口里用和关系还原出来的）
  跳过不重复计入。
- 顶层 `balance` 文案（`"5185.52 credits"`、`"$0.00"`、`"1,200,000 tokens"`）会被拆成
  「数值 + 单位」当作余额；若它其实就是某个数量窗口的剩余（MiniMax 就是这样），
  不重复展示。
- 到期积分优先取 `runsOutAt`（批次作废时刻），其次取 `resetsAt`（周期重置）；两者都有时取 `min(runsOut, 剩余)`。
- `runsOutAt` 不是「按当前速度会用完」的预测，只作为批次作废时刻使用。

## 隐私

- `magpie plugin` 显示 `reads nothing`：面板没有声明任何读取权限，也不会去请求厂商接口。
- 快照里的账号只用 `sha256(账号 ID)` 的前 8 位，不含真实账号 ID。
- 运行时生成的 `panel/live.js`（含你本地的额度数字）已被 `.gitignore` 排除，也不会打进 npm 包。

## 限制

- 面板只能追加在内置概览的末尾：magpie 的插件 UI 只在页面末尾（或供应商编辑页）提供 `panels` 插槽；用 `page.replaces` 接管整个用量页会顺带丢掉请求账本和上下文页，所以本插件刻意保持为面板。
- 数据新鲜度跟随 magpie 自身的配额刷新间隔（分钟级），不是实时。

## 文件

```
package.json      插件清单（magpie.panels、magpie.icon）
index.mjs         插件入口：读 quotas.json 与供应商注册表、聚合、写 panel/live.js
core.mjs          纯逻辑（窗口归一化、供应商聚合），入口之外的文件
panel/quota.html  面板页面（沙盒 frame）
panel/quota.css   面板样式，走 --magpie-* 主题变量
panel/quota.js    面板渲染；标题图标为内联矢量
icon.svg          插件图标源文件（清单里以 data URI 内嵌）
panel/live.js     运行时生成，不提交
test/             自测脚本：node test/preview.mjs、node test/panel-smoke.mjs
```

> 注意：magpie 的插件宿主会把入口模块**导出的每一个函数**都当成插件入口调用一遍，
> 所以 `index.mjs` 只能有 default 导出；纯逻辑放在 `core.mjs`（它不是入口文件）。
> 往 `index.mjs` 里多加一个 `export function …` 就会让插件加载失败。

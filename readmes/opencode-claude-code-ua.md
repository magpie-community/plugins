# UA PRO

独立的 Magpie 出站请求配置插件，内置 **Codex / Claude Code 请求模板**，支持 Responses、Anthropic Messages、Chat Completions 和 Gemini。模板随插件提供，可按连接或模型应用，支持版本保存、测试与回退。

npm 包名：[`opencode-claude-code-ua`](https://www.npmjs.com/package/opencode-claude-code-ua)。供应商 ID：`ua-pro`。无 npm 运行依赖。

> 当前源码版本为 **0.3.12**。本版本先通过 GitHub 提供，npm 暂未更新；请以管理页显示的实际运行版本为准。

## 安装与打开管理页

在 Magpie「插件 → 添加插件」中填写：

```text
opencode-claude-code-ua
```

或使用终端：

```sh
magpie plugin add opencode-claude-code-ua
magpie plugin login ua-pro
```

首次配置时，点击插件的 **登录**，选择 **连接上游 API key**填写地址和 Key，或选择 **打开 UA PRO 管理**进入连接和模板管理页。

### 已登录后再次管理或添加账号

首次填写完成、UA PRO 显示 **已登录**后，插件中心的卡片可能不再显示登录／管理按钮。后续操作改从供应商的账号入口进入，**不需要回插件中心找插件做设置，也不需要卸载重装**：

1. 打开 Magpie **模型 → 供应商**，点击 **UA PRO**。
2. 在账号区域点击 **添加另一个 UA PRO 账号**（添加账号入口）。
3. 选择 **打开 UA PRO 管理**，可管理已有连接、模板或添加新连接；选择 **连接上游 API key**，则直接填写另一个账号的地址和 Key。

“打开 UA PRO 管理”是打开管理页的登录方式，不代表必须重复填写已有 Key。也可以随时在终端执行 `magpie plugin login ua-pro`，再选择同一管理方式。

在 **管理连接**中查看、编辑已保存连接；它打开“连接与模型”，不执行模型请求。从 Magpie 打开管理页保存普通连接后，连接显示在 **UA PRO → 账号列表**中，而不是新增一个同名供应商。概览会显示实际注册状态。

概览中的 **宿主账号与连接对应关系**分别列出宿主账号数和 WebUI 连接数。宿主原生 Key 账号与 WebUI 保存的连接是两种来源；失效登录引用会明确标为未关联，不会当作可用 Key。只有确认后才可移除失效引用，其他账号、模板和签到记录保留。

若连接由独立 `node setup.mjs` 保存，需从 Magpie 打开管理页，点击 **同步到宿主**，再刷新供应商的模型列表。只有勾选独立显示才会有单独供应商；新增独立站点保存后，需要重载 UA PRO 插件。

也支持 GitHub 源码来源。在 Magpie 的手动添加框填写，或使用终端：

```sh
magpie plugin add "github:1466109846/ua-pro#main"
```

**发现页的 GitHub 卡片不一定安装源码**：当仓库对应的 npm 包存在时，Magpie 会优先安装 npm 的 `latest`。若 npm 尚未发布新版本，反复卸载重装该卡片仍会得到相同版本。使用上面的 `#main` 来源可明确选择 GitHub 默认分支。

npm 与 GitHub 来源二选一，不要重复安装。管理页侧栏显示实际运行版本，用于核对安装是否更新。

### 独立打开管理页

需要 Node.js 22 或以上。在下载的插件目录运行：

```sh
node setup.mjs
```

打开终端输出的本机链接。管理服务仅监听回环地址，链接只在本次会话有效。保存连接后，在 Magpie 重载插件；两处需要使用同一个 UA 状态文件。

## 快速配置

1. 打开 **连接与模型 → 添加连接**，填写名称、上游 Base URL、认证方式和 API key。
2. 点击 **获取模型**，选择需要的模型，追加或替换到列表，再保存连接。
3. 使用自动模板，或在 **应用模板**中选择一个已保存的模板版本。
4. 打开 **测试**，检查最终地址、模型、协议和模板，再确认发送请求。
5. 在 Magpie 重新获取模型或重载插件，载入保存的连接与路由。

客户端连接 **Magpie 本地网关**，使用 Magpie 网关密钥，不是上游 API key。模型引用可从测试页复制：

- 主池：`ua-pro/<模型 ID>`。
- 独立站点：`ua-pro-<siteId>/<模型 ID>`。

勾选 **在 Magpie 中独立显示此站点**并填写站点 ID，可将连接显示为独立供应商。最多 8 个独立站点，每个站点可配置多个账号；站点增删后需要重载插件。

## 连接与模型

Base URL 可填写站点根地址，或以 `/v1`、`/v1beta` 结尾的地址。远程地址要求 HTTPS，本机回环可使用 HTTP。自定义协议根路径可保留部署前缀，例如 `/anthropic/v1`；不要填写外域 URL、查询参数或具体请求路径。

| 认证方式 | 发送方式 |
|---|---|
| `api-key` | Messages 使用 `x-api-key`，Gemini 使用 `x-goog-api-key`，Responses / Chat 使用 Bearer |
| `bearer` | 始终使用 Bearer，填写纯 key |
| `custom` | 填写完整 Authorization 值 |
| `none` | 不发送认证 |

编辑同一地址的连接时，留空 key 可保留已有密钥；更换地址需要重新填写凭据。通过 Magpie 保存的账号凭据由宿主管理，不会复制到模板。

模型查询只读取列表，不发送生成请求。选择模型只修改草稿，保存后才生效；失败、取消或空列表不会清空手填内容。缓存模型会标明来源与时间，不会冒充本次查询成功。

每个连接可以设置默认协议、模型级协议覆盖，以及连接级或模型级模板绑定。自动协议是按模型名推断的，不保证上游支持；明确知道接口类型时，应保存固定协议。

测试页显示 **已保存的生产上游**。仅切换测试协议不会修改连接；需要保存时，点击 **将本次协议与模板保存为此模型路由**。插件不会在请求失败后自动更换 key、模型或协议。

## 模板与版本

插件内提供三份初始模板：

| 模板 | 用途 |
|---|---|
| Codex | 内置只读的 Responses 请求规则 |
| Claude Code | 内置只读的 Messages 请求规则 |
| Claude Code VS Code 2.1.316 | 可编辑的 Messages 请求模板 |

自动绑定按最终上游协议选择：Responses → Codex，Messages → Claude Code，Chat / Gemini → 普通转发。

要自定义规则：

1. 在 **模板库 → 新增模板**中选择一个模板作为基线。
2. 修改名称、UA、请求头或正文规则，**保存新版本**。
3. 预览或测试后，**应用**到指定连接或模型。

保存与应用分开。保存 v2 不影响仍绑定 v1 的连接；回退时选择历史版本重新应用。被引用的版本不能删除，归档不会中断已有绑定。JSON 导入只创建草稿，不自动保存或应用。

请求头支持覆盖、补缺、删除和保留；参数按 `defaults → overrides → remove` 处理。模板不能覆盖 Authorization、API key、Cookie 等认证头，也不执行用户脚本。默认保护模型、消息、工具与流式选择；计数接口不执行生成参数覆盖。

内置模板的会话与正文兼容规则可能影响提示前缀、token 用量或缓存。可复制为自定义模板后查看、修改或关闭。UA 和兼容字段不证明官方客户端身份，也不提供额外账号权限。

### Messages 反代要求提示缓存键

`gpt-6-astra-cc-format` 使用 Messages 接口。自动路由会识别这个精确模型名；连接若已固定为其他协议，请给该模型单独设置 Messages 覆盖。

当反代返回 `prompt_cache_key is required` 时，可复制 Claude Code 模板，在 **请求正文 → 提示缓存键（高级，反代）**中选择 **会话缓存键**，保存新版本，再仅应用到需要它的模型。插件在最终出站正文中按会话、模型和连接凭据作用域补缺，保留已有非空键，不向计数请求添加；未开启的模板不改变正文。

这是反代扩展，不是标准 Messages 必填字段。不要把 `{{session.id}}` 填入正文 defaults，它不会在该区域展开；也不要让所有会话共用一个固定值。缺少可用会话信息时会明确报错，不生成每次变化或跨会话共享的缓存键。

## 余额与签到

### 在 Magpie 用量页查看余额

UA PRO 中已配置的连接可以复用模型 Key 查询站点支持的用量接口：

- **NewAPI**：显示 Key 剩余额度；站点明确授权账号级查询时，才显示账号余额。Key 额度不等于账号总余额。
- **不限额 Key**：不会显示成零余额。站点额度倍率无法确认时，金额会标注估算。
- **仅支持累计消耗的站点**：显示已用金额与“余额未知”，不把未知余额当成 0。

在 **余额与签到**页点击 **刷新全部余额**，可同时读取站点账号余额和已配置连接的 Key 用量。Key 余额不依赖签到凭据；签到账号缺少凭据、读取失败或被停用时，不会阻止对应连接的 Key 余额查询。两类读数分别展示，不混合汇总。

用量刷新只查询数据，不会自动登录或签到。用量页显示的是添加到 UA PRO 的连接，余额是否可读取取决于站点接口与权限；目前不提供余额趋势图。

如果提示 **Key 用量接口返回的不是 JSON**，该接口可能返回了网页、验证页或空响应，不代表模型 Key 无效。已经能用 Cookie 读取站点账号余额时，请将该账号明确绑定到相应连接；不要用 Key 替代 Cookie，也不要绕过站点验证码。

填写连接地址和模型 Key 时，也可在 **余额与签到账号**旁点击 **在此添加 Cookie / 令牌（可选）**，就在当前页创建站点账号。连接名称、站点根地址会自动带入；选择 Cookie 或系统访问令牌并补充用户 ID 后，创建的账号会选入当前连接草稿，再点击 **保存连接**完成绑定。这个步骤不是必填项，跳过仍可正常保存和使用模型 Key。

账号保存只保存本地配置，不执行登录、刷新或签到，也不会把模型 Key 当作站点凭据。定时、额度倍率、历史记录和后续编辑仍在独立 **余额与签到**页管理。

### 添加签到账号

打开 **余额与签到 → 添加账号**，选择站点类型：

| 站点类型 | 签到所需凭据 |
|---|---|
| NewAPI | 站点根地址、数字用户 ID、登录 Cookie 或有签到权限的系统访问令牌 |
| AgentRouter | 站点地址、登录用户名和密码；用户 ID 可留空，由成功登录确认 |

NewAPI 使用站点签到接口。AgentRouter 通过登录领取每日额度；成功返回的 session 仅保存在本机，用于之后的余额查询。模型 API key 不能替代签到账号凭据。

添加账号后：

1. 在 **连接与模型 → 编辑连接 → 余额与签到账号**中选择对应账号并保存；仅在账号页填 Cookie、看到余额，还不代表该账号已绑定给宿主连接。
2. 从 Magpie 打开的管理页会把绑定同步到对应宿主账号，保存反馈应为“已保存并注册到宿主”。若提示尚未确认，先同步或重载插件，再在 Magpie **用量**页刷新余额或点击 **立即签到**。

绑定不修改模型 Key、协议或模板。同站点、同数字用户 ID 的账号修改签到类型或登录用户名时，已有 PAT／Cookie 和余额记录保留；更换站点或用户 ID 不会沿用原账号凭据。

一般只能绑定同站点账号；AgentRouter 支持 `agentrouter.org` 与 `ps.air-outer.com` 的双地址配置。已删除或异站绑定会提示失效，不会自动换成另一个账号。站点要求验证码时，需前往站点完成验证。

### 每日定时签到

在账号编辑页开启定时签到，设置每天的时间和 IANA 时区，例如 `Asia/Shanghai`。

- 需要 Magpie 插件进程保持运行；关闭管理页面不影响定时任务。
- 独立运行 `node setup.mjs` 不启动定时签到。
- 开启定时后仍可手动签到；同日已尝试或领取时，插件定时器不会重复提交。
- 错过指定分钟不补跑，失败或结果未知不自动重试。
- 不要同时开启 Magpie 自身的自动签到计划，以免两套计划重复执行。

签到是否领取成功以站点返回为准。余额变化和消耗增量来自两次成功读取，不等于“今日用量”。

## 测试请求

| 测试层次 | 行为 |
|---|---|
| 本地转换预览 | 不联网，展示脱敏后的 URL、请求头、正文和规则变化 |
| 模型列表检查 | 读取模型目录，不证明模型可以生成回复 |
| 实际模型请求 | 经确认后发送一次请求，支持普通／流式，可能产生费用 |

发送前的确认框展示最终地址、模型、协议和模板。测试路径覆盖只影响本次测试；自定义正文不会因切换模型或协议而被静默覆盖。HTTP 200 中的错误 JSON 或错误 SSE 仍显示为失败。

### 验证入站、上游与出站 UA

发送一次请求后，在 Magpie **用量／请求记录**中找到对应记录，核对入站路径、上游路径和出站 UA。Responses 转发记录可这样阅读：

| 记录字段 | 示例与含义 |
|---|---|
| 入站 | `/v1/responses`：客户端请求 Magpie 时使用的接口 |
| 上游 | `/v1/responses`：Magpie 向模型服务转发时选择的接口；与入站相同表示没有跨协议转换 |
| 出站 UA | `codex_cli_rs/0.159.0 (Windows; x86_64) …`：该条记录显示的出站客户端标识，可核对是否使用了预期模板 |
| 流式、输入／输出用量和耗时 | 核对请求模式、模型及执行结果，不代表所有模型都具有相同能力 |

Messages 模型应核对上游路径为 `/v1/messages`；模型服务可能与客户端使用不同协议，要以上游路径为准。UA 是请求标识，不是账号授权证明；这一行记录也不能证明全部请求头和正文参数都已被上游接受。若要检查 `prompt_cache_key` 等字段，需查看对应请求的脱敏出站预览或实际请求正文，而不能仅凭 UA 判断。

## 数据与安全

从 Magpie 启动时，默认把数据保存在 **Magpie 配置目录下的 `ua-pro/`**，不写入可被升级或卸载替换的插件安装包。实际路径可在管理页 **设置 → 存储位置**查看。

| 默认文件（相对于数据目录） | 用途 |
|---|---|
| `ua-pro.json` | 模板、连接、绑定及本地保存的连接凭据 |
| `ua-pro.json.models.json` | 模型目录、来源与时间，不含 key |
| `accounts.json` | 站点账号、Cookie 和显式保存的登录凭据 |
| `schedule-claims/` | 每日签到防重复记录 |

`uaFile` 插件选项或 `UA_PRO_FILE` 环境变量可指定 UA 状态文件的绝对路径，其他账号数据随该目录保存。独立 `node setup.mjs` 的默认数据目录仍是插件的 `runtime/`；要与宿主使用相同数据，需明确指定同一个 UA 状态文件。

升级时，只会复制当前本插件安装目录中仍存在的配置到尚未使用的宿主持久目录，不覆盖已有数据，原文件保留。若旧安装目录已经被删除，缺失的 Key、Cookie 或模板不能从宿主登录引用恢复。

本地凭据以文件权限保护的明文保存，不是加密保险库。不要分享数据目录、`runtime/`、配置副本或含秘密的自定义请求头。仅连接自己拥有或已获授权的 API。

## 常见问题

**如何再次打开管理页？**

已登录后从 **模型 → 供应商 → UA PRO → 添加另一个 UA PRO 账号 → 打开 UA PRO 管理**进入，不必回插件中心找设置。终端也可执行 `magpie plugin login ua-pro`。管理会话过期后需重新打开，刷新页面不能延长授权。

**宿主能获取模型，独立管理工具却失败？**

独立 Node 进程不继承 Magpie 账号代理。可从 Magpie 打开管理页，或为独立进程配置网络环境。

**模型列表成功，生成却返回 404？**

检查上游协议、协议根路径和模型引用。目录读取成功不代表站点支持该生成接口。

**保存后为什么没有生效？**

模板要先保存、再应用。连接、站点或模型协议更新后，在 Magpie 重新获取模型或重载插件，并重新打开管理页。

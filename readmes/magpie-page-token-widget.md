# magpie-page-token-widget

> [English](README.en.md) · 中文 · 当前版本 0.4.2（变更见 [CHANGELOG.md](CHANGELOG.md)）

把 iPhone 桌面的额度组件接进 Magpie：装上这个插件，扫一次码，手机上就能显示 Codex、MiniMax、GLM 各家套餐的剩余额度与真实 Token 用量。

装这个插件不需要再跑安装脚本、装 Node.js、建计划任务，也不需要你自己开端口转发：默认是 Tailscale 模式，插件自己把服务跑起来、自己建好尾网里的转发，手机扫一次码就配对好了。

> 数据来自你自己的 Magpie，脚本里不含任何密钥。组件显示的仍是 Magpie 的口径。

插件页分两栏：左边一栏是扫码配对（二维码、配对地址、倒计时、复制按钮）和「在 iPhone 上」的四个步骤；右边一栏依次是状态、数据更新、显示哪些订阅、设备管理、网络连接、高级设置。网卡多的机器上，「尾网里的 iPhone」「这台电脑的网卡」「手机可以从这里连」三张清单默认折起来，标题上写着各有几台。

## 它做什么

- 插件页给出一个二维码。用 iPhone 的相机扫一下，Safari 打开配对页，下载组件脚本，用 Scriptable 打开它，长按桌面加组件就行了。
- 组件里显示每家订阅的剩余额度、5 小时与周额度窗口的百分比、重置倒计时和今日 Token；七日趋势和各家排行在点开组件后的手机用量页上。参数可以选订阅（`codex`、`minimax`、`glm`，或 `codex@账号名`），也可以把百分比换成已用（`|used`）或换回剩余（`|remaining`）；不填参数时听插件页里「小组件」那块的选择。
- 插件页分两栏：左边是扫码配对（二维码、配对地址）和「在 iPhone 上」的四步；右边在宽屏上再分两列——先是**状态**、**数据更新**（多久读一次）、**显示哪些订阅**（勾选手机上要出现的卡片，**拖着左边的点可以换顺序**，手机和组件都照这个顺序排）、**小组件**（组件显示剩余还是已用、小号组件看哪一张卡）；另一边是**设备管理**（已配对的手机，可单独撤销，撤销之后可以整行删掉）、**网络连接**（尾网状态、连接路径、本机网卡）、**高级设置**（端口和网关这些很少改动、只看了一眼就行的参数）。网卡多的机器上，网卡、尾网里的手机和候选地址这三张清单收在「展开」里，页面短了一大半。
- 点一下手机上的组件，Safari 会打开手机版用量页：每家订阅的剩余额度、今日与近七日的 Token、模型／厂商／客户端排行，和电脑上看到的是同一份数据。
- 服务只读 Magpie 的本地接口。默认（本机监听 + Tailscale 转发）时，服务只在本机打开，手机经尾网的转发进来，令牌存放在 Magpie 自己的目录里。

## 需要什么

- Magpie（桌面版，插件宿主是 Bun）。
- iPhone 上的 [Scriptable](https://scriptable.app/)。
- Tailscale：**只有默认模式需要**。电脑和 iPhone 都在同一个尾网里，插件靠它找到地址、自己建转发。改用自己的服务器或可信内网地址时，Tailscale 不再是必需品。

三种连接方式（默认 Tailscale、自定义外部地址、局域网直连）见下面的「三种连接方式」。

## 安装

在 Magpie 里打开插件页，或者用命令行：

```bash
magpie plugin add magpie-page-token-widget
```

从源码装：

```bash
magpie plugin add ./magpie-page-token-widget
```

## 配对

1. 在 Magpie 里打开「插件 → iPhone 额度组件」。
2. 插件页会显示 Tailscale 的状态。电脑和 iPhone 都在同一个尾网里时，这里会显示尾网地址和一张二维码。
3. iPhone 用相机扫码，在 Safari 里打开配对页，点「下载组件脚本」。
4. 在「文件」App 里打开刚下载的 `UsageWidget.js`，选「共享 → 用 Scriptable 打开」。
5. 长按 iPhone 桌面空白处，添加 Scriptable 小组件，选择 `UsageWidget`。

配对码只能用一次，而且只活十分钟：十分钟之后它就废了，插件页会自己换一个新的出来（不用手点），所以第一次配对不用先去点「重新生成配对码」；用掉之后旧码立刻作废。**每配一台手机，它都会拿到属于自己的那枚只读令牌**，服务端只留这枚令牌的哈希，明文只在配对的那一次出现，之后再也拿不出来。一台手机作废，只停这一台。

为什么扫了码还要令牌：配对码是**门**，只能用一次、十分钟就作废；令牌是手机自己换到的**钥匙**，要能一直用下去。Scriptable 存不住 cookie，手机每次问用量都得带一个长期有效的凭证；一枚一枚发，是为了「停掉一台」只停这一台。你自己扫自己的码，扫码那一步已经证明了操作的是你本人，所以令牌全程不用你手抄：手机扫完码自己换到一枚，服务端只留它的指纹。

0.1 时代那枚给所有手机共用的共享令牌已经没有了：升级之后它立刻作废，手里还拿着旧令牌的手机要重新扫一次码配对，重新拿到自己的令牌。

配对码不是可以随便猜的：同一个配对码连续猜错十次就锁五分钟（配对网页那道门宽一些，三十次才锁），锁的是这个码本身，不是那台机器。原因是转发过来的手机在服务器看来都是本机的回环地址，按地址锁的话，尾网上任何一个人猜错十次就能把所有人的配对都关上。请求头里的 `X-Forwarded-For` 谁都能写，服务器不看它。

服务还有一本总账：五分钟里猜错一百次（不管猜的是哪个码），配对页、组件脚本和配对接口一起先关上，等五分钟满了自动恢复。电脑上点一次「重新生成配对码」会把总账清空，手动马上就能再配。真正让配对码难猜的不是这两道门，而是它有九十六位随机数、只活十分钟、只能用一次。

手机脚本把令牌存在 Scriptable 的钥匙串里，同一台 iPhone 上的所有组件（小、中、大号都算）共用这一枚令牌。

不想扫码也行：插件页的「设备管理」里可以给某台手机单独发一枚令牌，把它和「服务地址」填进 `scriptable/SetupUsageWidget.js`（在 Scriptable 里新建一个脚本粘贴运行）也行。服务地址可以填 Tailscale 地址（`http://100.x.x.x:8790`）、自己内网里的地址（`http://192.168.1.50:8791`），也可以填你自己配好的 HTTPS 域名（`https://my-server`）。**公网上的明文 HTTP 地址会被拒绝**，理由和规则见下面「三种连接方式」。

## 设备管理

「设备管理」里列出所有配过的设备：名字、什么时候配的、最后一次是什么时候、什么时候撤销的。每一条都能改名字，都能单独撤销。**撤销＝这枚令牌立刻作废、这一行留着做个记录；撤销过的那一行还能再「删除」，删掉之后它从名单上消失。** 在用的手机不能直接删：得先撤销（撤销才是停掉它的那一步），再删。撤销过的行排在最后，字也淡一些。想加一台新手机，点「给这台手机一个令牌」，把生成的那枚明文令牌填进手机即可（只显示这一次）。

「高级设置」里的「配对记录」是本机的一本流水账（配对的时间、名字和地址，里面没有令牌），删掉设备不会抹掉它。

## 数据更新

服务不会每个手机请求都去读一遍 Magpie。它拿着一份快照，快照一分钟内是新鲜的，直接给；过期了才去读，而且所有同时来的请求共用同一次读取。

读的时候最多等两三秒：读回来了就立刻给新的；还没回来就先给旧的，标成「旧数据」，后台继续读。

平时多久读一次可以选：

| 策略 | 说明 |
|---|---|
| 智能更新（默认） | 有人看的时候每分钟一次；十分钟没人看改成五分钟一次；半小时没人看就基本不自己读了，等有人来再说 |
| 每分钟 | 固定每分钟读一次 |
| 每两分钟 | 固定每两分钟读一次 |
| 每五分钟 | 固定每五分钟读一次 |

在插件页改一下就立刻生效，不用重启 Magpie。

## 网络连接

「网络连接」里能看到：Tailscale 装没装、连上没有、本机的尾网地址、MagicDNS 名字、同一尾网里的 iPhone，以及现在这通连接走的是哪条路。

连接分三种，看的时候别混：

- **直连（Direct）**：Tailscale 在两台机器之间直接加密通信，通常是同一个局域网里自动找到对方地址之后走这条路，最快。
- **经由尾网中继设备（Peer Relay）**：两台机器之间没有直连路径，借了尾网里第三台设备转发。
- **经由 Tailscale 中继服务器（DERP）**：连不上也没有中继设备时，流量走 Tailscale 自己的中继服务器兜底，最慢但最稳。

读不出来的时候显示「还不知道」，不猜。「诊断连接」按钮会真的 ping 一次那台手机，把结果写出来；平时不会自己 ping，省得一直起 Tailscale 子进程。

本机的网卡也在这一块里列着：网卡名、IPv4、IPv6、子网前缀、是 Tailscale 网卡还是 Wi-Fi／有线／虚拟网卡。**这些地址只给电脑上的你看，手机接口拿不到。** 列出它们是为了排障：手机连不上的时候，先看看这台电脑在局域网里的地址，再看尾网地址是不是变了。

**默认仍然走 Tailscale**，不会因为这台电脑有个 192.168.x.x 就让手机改走局域网直连。原因是：局域网直连要处理明文 HTTP（或另配 HTTPS）、DHCP 换地址、iOS 的本地网络权限等等一串事情，做不好就是新的安全口子；而且尾网地址在手机和电脑上都是稳的。

想走自己的路，请看下面那一节：那是自己选、自己填、自己负责的，不是自动发生的。

## 三种连接方式

这是三件事，看的时候别混。控制台「网络连接」里随时能看出当前用的是哪一种。

### 一、默认：Tailscale

- 装好就是这样，什么都不用配。插件找到本机的尾网地址，自己在尾网里建一条转发（`tailscale serve --tcp`），手机从 100.x 的地址连进来。
- 控制台留在 127.0.0.1，只有手机那一侧在尾网上。尾网里的请求不会被当成本机的请求，所以手机看不到控制台，也拿不到控制台的令牌。
- 端口上已经有别人的转发时，插件不会动它，控制台会说明转发没建起来。
- 手机连不上时先看三件事：iPhone 在不在这个尾网里、Tailscale 是不是登录着、两端之间有没有直连路径。
- 走哪条路看「本机连接路径」：**直连（Direct）**是两端直接加密通信，通常是同一个局域网里自动找到对方地址，最快；**经由尾网中继设备（Peer Relay）**是借了尾网里第三台设备转发；**经由 Tailscale 中继服务器（DERP）**是既连不上也没有中继设备时的兜底，最慢但最稳。这三条路都不保证一定通——DERP 是最后的退路，不是「一定能连上」的保证。

### 二、自定义外部地址：自己的服务器、反向代理或自建 Headscale

在「网络连接」的输入框里填一个地址，手机配对时拿到的就是这个地址，组件和手机上的用量页都用它。填了以后插件不再建 Tailscale 转发，这件事上不再需要 Tailscale 的任何东西。

能填什么：

| 地址 | 能不能用 | 说明 |
|---|---|---|
| `https://my-server` / `https://my-server.example.com` | 能 | HTTPS 地址可以写任何域名。令牌和用量在传输里是加密的。 |
| `http://192.168.1.50:8791`、`http://10.0.0.7:8791`、`http://172.16.3.9:8791` | 能 | RFC1918 的私网地址。 |
| `http://100.64.0.5:8791` | 能 | Tailscale（和自建 Headscale）的地址段。 |
| `http://[fd00::1]:8791`、`http://[::1]:8791` | 能 | IPv6 的 ULA 和本机回环。 |
| `http://box.local:8791`、`http://myserver:8791` | 能 | 保留给内网的域名，或本机解析器里的单段名字。 |
| `http://example.com`、`http://93.184.216.34:8791` | **不能** | 公网上的明文 HTTP：令牌会在路上被看见。 |

服务器上的检查和手机上的安装器用的是同一套规则，所以两边不会给出相反的结论。

升级到 0.3.3 之后，配置里存着的地址会重新按这套规则过一遍：以前填过的**公网上的明文 HTTP 地址不再被接受**，插件会把它从配置里去掉，并在控制台上写明原因，然后回到 Tailscale 的转发。内网地址、Tailscale 地址和 HTTPS 地址都不受影响，手机上已经配好的令牌也不用重新配对。

反向代理的要求：

- **这一版不支持带路径的地址。** 请用一个独立域名，把它的**根路径**转到插件服务，然后填 `https://my-server`。填 `https://my-server/widget` 会被明确拒绝，而不是半通不通。
- 代理要转到**手机那一侧的端口**（默认 8791），不是控制台的端口（默认 8790）：控制台永远只留在本机，代理只应该把手机那一侧放出去。
- 代理必须把原来的 `Host` 原样传过去（`proxy_set_header Host $host;`）。插件靠它认出「这个请求是冲着我来的」，伪造的 `Host` 会被拒绝。
- 插件**不信任** `X-Forwarded-Proto`、`X-Forwarded-Host` 这些请求头：谁都能写它们。走 HTTPS 还是 HTTP，只看你在控制台里填的那个地址。
- 代理自己终结 HTTPS、再用 HTTP 回源到插件，是可以的：插件只按你填的地址判断对错，不看中间那一段。

要当心的事：

- 走明文 HTTP 时，令牌就在里面走。除非地址是上面表里那些可信内网，否则只在自己信得过的网里用。
- 手机直连局域网地址时，iPhone 会问「本地网络」的权限，要允许。
- 地址会动：路由器换了地址，手机就找不到了，那时候来控制台改一下。
- 防火墙：手机要从局域网进来，Windows 的防火墙可能会挡住这个口，第一次要放行一次（只放行「专用网络」就够了）。

### 三、LAN 直连：手机不进尾网

不想用 Tailscale，只在同一个局域网里用：让手机那一侧直接在这台电脑的局域网地址上开一个口，手机走局域网地址连进来。

- 开的只有**手机那一侧**这个口，控制台永远关在本机（127.0.0.1），手机接口里没有控制台。
- 在「网络连接」里点某个网卡后面的「手机从这里连」，或者自己填地址（`http://192.168.1.50:8791`）并在「这台电脑的网卡」里选一个地址，插件就在那个地址上打开手机那一侧的端口。
- iPhone 会问「本地网络」的权限，要允许；Windows 防火墙第一次要放行一次。
- 电脑的局域网地址会变（DHCP），手机就找不到了，这时候回控制台重新选一次。
- 这条路是明文 HTTP，令牌在里面走。

**怎么彻底关掉它**：点「网络连接」里的**「恢复 Tailscale 默认连接」**。这个动作会清掉自己填的地址、清掉文件里记着的网络设置、**把局域网那个口真的关掉**（不是只改配置），再把 Tailscale 的转发建回来。关完之后控制台会写明现在生效的是哪一种连接方式。

## 手机上的用量页

点一下桌面上的组件，Safari 会打开手机版的用量页：每家订阅的剩余额度、今日与近七日的 Token、模型／厂商／客户端排行，和电脑上看到的是同一份数据。

页面用组件里的那个只读令牌打开，令牌只走地址栏的 `#token=` 一段，页面打开后立刻把它抹掉，之后由这个页面自己记着（存在这台手机上，下次直接开，不用再输一遍）；组件那边另存一枚，本来就是它把令牌拼进地址的。手机版页面只在尾网这一侧提供（填了自己的地址以后，就是在你自己的网上），电脑上的控制台仍然只在本机。

这枚记住的令牌留三十天：手机上的页面记住三十天（过期了再扫一次码就行，从组件点进来不会问你要令牌——组件每次都自己带上）。 Safari 要是自己把网页数据清掉了，那也只是一次重新扫码的事。

手机上的页面右上角有一个「断开」：按一下就把这台手机上记住的令牌抹掉，并且请服务把 PC 名单上那一行也划掉（服务答话的时候它才真的消失；服务没答话，那一行还在，可以在插件页的设备管理里删掉它），下次打开要重新扫一次码（别的手机不受影响）。在 Magpie 的插件页里「撤销」那一台，效果一样——那枚令牌立刻作废，行留作记录，可以再点「删除」划掉。

## 组件参数

| 尺寸 | 内容 | Widget Parameter |
|---|---|---|
| 小号 | 单家额度、重置倒计时、今日 Token | `codex`（默认）、`minimax`、`glm`；某账号写作 `codex@账号名`；加 `\|used` 改显已用，加 `\|remaining` 改回剩余 |
| 中号 | 每页最多 6 个；1–4 个并排，5–6 个两行三列；今日 Token；重置时间和七天占比写在两行上（5–6 个订阅挤成两行时只留 5 小时额度，也没有这两行） | 留空；`page=2` 查看第二页；加 `\|used` 把每张卡都换成已用，加 `\|remaining` 换回剩余 |
| 大号 | 每页最多 6 个；两列卡片，显示主额度、重置时间及第二窗口百分比；今日与近七日 Token | 留空；`page=2` 查看第二页；加 `\|used` 把每张卡都换成已用，加 `\|remaining` 换回剩余 |

参数里的账号名是现在的账号名。控制台「显示哪些订阅」里，每一行都写着组件认得的参数，照抄过去就行。账号改了名字以后参数会找不到，小号组件不会再空着：它会先给你看第一张卡，旁边写一句「没有找到 xxx」。

**参数现在是可选的**：插件页的「小组件」里已经能选「数字是剩余还是已用」和「小号组件显示哪一张卡片」，选完所有组件都照这个来（不用去 Scriptable 里敲参数了）。组件参数还在，只是变成了临时改一次的用法：填了就以填的为准，只影响这一个组件；不填就听插件页的。

### 「剩余」是什么

厂商的套餐额度是按一个滚动窗口算的（比如 5 小时一个窗口、一周一个窗口）。这个窗口里你用了多少，是同一个数的两面：

- **已用**：这个窗口已经用掉的比例。
- **剩余**：还能用的比例（剩余 = 100% − 已用）。

所以「额度剩余 38%」的意思是：这个窗口还剩 38% 的额度。旁边的倒计时是**这个窗口什么时候翻篇**（翻篇之后剩余回到 100%）。

它和 Token 用量不是一回事：额度剩余是**套餐给了多少、还剩多少**；今日 Token、近七日 Token 是**实际发了多少请求**。有的套餐不限量，那就没有额度这一行，只剩 Token 用量。

### 组件上写着「令牌无效，请重新配对」

这三种话现在分得清了：

- **令牌无效，请重新配对**：这枚令牌被撤销了，或者服务这边把这台设备删了。组件会自己把这枚令牌从钥匙串里抹掉，请服务把 PC 名单上那一行也划掉（服务答话的时候它才真的消失），然后回到没有配对的样子——重新扫一次码就好。站在服务前面的代理自己给的 401 不会被当成令牌作废：那时候组件说的是「服务返回 401」，令牌留着不动。
- **服务没有回答** / **服务返回 N**：网络不通、服务正忙或者服务报错了；组件会先把上一次的结果摆出来。
- **连不上服务**：压根没连上。

旧版本只有两句话：令牌不对时说「令牌无效，请重新设置」，其余的（服务报错、断线）一律说「离线缓存」，看着像一切正常，其实服务早就没在答话了。更早的版本还有一个坑：钥匙串里存着一枚服务不认的旧令牌时，脚本每次都跳过「拿配对码换新令牌」这一步，重新扫码、重新下载脚本都救不回来，只能先手动清掉钥匙串。现在脚本带着新配对码时会**先试换发**，失败才退回旧令牌；换发成功时，会请服务把旧令牌的那一行从 PC 名单上划掉（服务答话的时候它才真的消失）。新令牌先写进钥匙串，再去收拾旧的那一行——配对码只能用一次，中途关机也不能把它弄丢。

数字前面永远写着方向：「剩余」还是「已用」。进度条在亮色和暗色里都是同一种墨（只是深浅不同），夜里不会发亮成警报；只有数字在快用完的时候才会变成橙色或红色。

## 生命周期

组件随 Magpie 运行。关掉 Magpie 之后，手机上显示的是最后一次拿到的结果，重新打开 Magpie 就会更新。这和原来那个用计划任务常驻的服务不同，是"插件"这个形态的取舍。

Magpie 停止或重载这个插件时，插件会走一遍自己的清理：关掉自己开的监听、撤掉自己建的转发。进程被强杀时做不了这一步，见下面「卸载」。

## 端口

服务默认听 8790，手机那一侧是 8791。端口上冲突时换一个：

```bash
magpie plugin options magpie-page-token-widget '{"port":8890}'
```

改完要重启 Magpie。默认（Tailscale）模式下，插件会在尾网里给这个端口建一条转发（`tailscale serve --tcp`），手机从 100.x 地址连进来；端口上已经有别人的转发时，插件不会动它。

转发指向的是手机那一侧的端口（默认比服务端口大 1，即 8791），控制台留在 127.0.0.1:8790。尾网里的请求落在这条转发上，不会被当成本机的请求，所以手机看不到控制台，也拿不到令牌。改用自己的外部地址以后，就不再建这条转发。

插件会把自己建的转发记在配置文件里（端口和指向哪里）。重启之后它认得自己的转发，不会重复建；老版本留下的转发会被搬到手机那一侧；别人的转发它既不碰也不删——只凭端口相同不算「是我的」。插件正常停止或卸载、并且那条转发仍然指向它记下的地方时，它才会把转发撤掉。

`tailscale serve --bg --tcp=8790` 是 Tailscale 里的长期设置：进程被强杀（崩溃、断电）时它留在那儿，不会自己消失。这种情况下插件下次启动会发现它还在、而且指向自己，会接着用；要自己收掉就 `tailscale serve --tcp=8790 off`，然后 `tailscale serve status` 看看还剩什么。

端口和网关都是 Magpie 启动这个插件时给的参数：端口是插件自己听在哪儿的地址，网关是插件去读的那个 Magpie。插件自己搬不了家，所以它们留在 Magpie 的启动参数里。想换端口或网关，在 Magpie 的插件设置里改：

`magpie plugin options magpie-page-token-widget '{"port":8890,"gatewayURL":"http://127.0.0.1:3500"}'`

改完重启 Magpie；手机那边的地址带着端口，换了端口手机上存的地址就旧了——重新跑一次 `scriptable/SetupUsageWidget.js`、把新地址（和令牌）填进去就行，令牌本身仍然有效，不用重新配对。

插件读的是 Magpie 自己的本地接口，默认是 `http://127.0.0.1:3425`。**这个网关地址必须指着本机**（`127.0.0.1`、`::1` 或 `localhost`）：插件只去读这台电脑上的 Magpie，填成别的地址会被明确拒绝（控制台会写出原因），而不是把你的请求发到那台机器上去。控制台的**高级设置**里能看见现在读的是哪里（只是看一眼），但改它要去 Magpie 的插件设置里：这个地址换了要重启 Magpie 才算数，在 Magpie 设置里改了但还没重启时，插件页里显示的仍是旧地址，要等重启后才一起换过来。

## 兼容性

- 需要 Magpie `0.1.3681` 以上（`package.json` 里写着）。
- 额度读的是 Magpie 已经缓存好的那份（`/v1/magpie/quotas?kept=1`），不额外去问供应商。
- 今天的 Token 读 `/v1/magpie/usage?period=today`，一次请求就拿到总数、分时、各厂商和各账号。**老版本 Magpie 没有这个接口时会自动退回老办法**（`/v1/magpie/usage/requests?period=today` 加逐账号的请求），组件上的数字照常有。退回只在网关明确回答「这个接口没有」（404、405、501）时才发生；网关临时出错（500、超时、断网）不会去逐账号重问，而是保留上一次读到的数字并标成「旧数据」。「这个接口没有」这件事会被记住一阵子，不会每次刷新都去问一遍。
- 七日趋势和模型／厂商排行读 `/v1/magpie/usage/requests?period=7d&limit=1`：这个接口才带 `by.model`、`by.agent` 这些分组，换成别的接口会把排行和趋势丢掉，所以保留。
- 周期参数 `week` 在 Magpie 里不认（会被当成 30 天），七日要用 `7d`。

## 卸载

```bash
magpie plugin rm magpie-page-token-widget
```

插件被停止或移除时，插件会关掉自己开的监听、撤掉自己建的转发（只撤它自己记着的那条）。但有一件事做不到：进程被强杀（崩溃、断电、被强退）时来不及做这些，Tailscale 里的转发会留着，需要自己收一次：

```bash
tailscale serve --tcp=8790 off
```

## 隐私

- 服务只读 Magpie 的本地接口（默认 `127.0.0.1:3425`，只能是本机），不写 Magpie 的配置，不碰登录信息。
- 令牌是本机随机生成的，只读，存在 Magpie 的配置目录里；服务端只留哈希。没有共享令牌：一台手机一枚，撤销哪一枚就只停哪一台。只有这台电脑上的插件页，和带着配对码的手机，才能拿到令牌。
- 局域网地址只出现在电脑上的控制台里，手机接口不提供。
- 默认（Tailscale）模式下，服务只在本机（127.0.0.1）上监听，手机是经尾网的转发进来的，没有公网入口，也不需要防火墙规则。改用自己的地址以后，手机那一侧会在你选的地址上开一个口（**只有手机那一侧**，控制台永远关在本机），这时防火墙要放行一次。这条路是不是明文，看你填的是什么地址：填 HTTPS 域名时手机到代理之间是加密的（代理到插件之间仍是明文 HTTP），填内网地址时全程明文。

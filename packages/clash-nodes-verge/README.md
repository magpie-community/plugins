# @magpie-community/page-clash-nodes-verge

Pick a node from your **Clash Verge Rev** subscription and assign it to a provider, or to each account of a provider, inside magpie's window.

Install it from magpie's **Plugins › Discover**, or with `magpie plugin add @magpie-community/page-clash-nodes-verge`. It then has a tab, **Clash 节点** (titled in the window's language: 梯子节点, 梯子節點, Clash ノード), under Plugins in the sidebar, in the app and in `magpie web`.

Adapted from [player462/magpie-clash-nodes](https://github.com/player462/magpie-clash-nodes) (MIT) for Clash Verge Rev: reads `profiles.yaml`'s `- uid:` shape, follows Verge's kernel paths and named-pipe controller, and won't kill Verge's own mihomo process. Mechanism unchanged: the plugin spawns a separate mihomo instance that exposes each node on `127.0.0.1:18001+` as a local HTTP port, then writes `providers.json`'s `proxy` / `accountProxies` so magpie's next request per account picks the matching port.

## Why it exists

magpie's proxy setting accepts `http://`, `https://`, `socks5://`, `socks5h://` — not VLESS / SS / Trojan / Hysteria subscriptions. Clash Verge already turns those subscriptions into usable local exits; this plugin re-exposes each node as its own loopback HTTP port, so magpie can pick per account.

## Requirements

- magpie 0.1.418+ (`accountProxies` support)
- Clash Verge Rev running, subscription updated
- Default lookups:
  - Subscription index: `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\profiles.yaml`
  - Subscription files: `<same dir>\profiles\<uid>.yaml`
  - Kernel: `%ProgramFiles%\Clash Verge\verge-mihomo.exe`, `%LOCALAPPDATA%\Programs\Clash Verge\verge-mihomo.exe`, `%ProgramFiles%\Clash Verge\resources\sidecar\mihomo.exe`

Override with environment variables when these paths don't match your install:

| Variable | Purpose |
| --- | --- |
| `CLASH_VERGE_DIR` | Verge config dir (holding `profiles.yaml` and `profiles\`) |
| `MIHOMO_EXE` | mihomo kernel path |
| `MIHOMO_CONFIG` | Master config (referenced when generating port config; usually Verge's `config.yaml`) |

## What it reads

`providers:list` is the only permission `package.json` declares (`magpie.permissions`) — the page reads magpie's provider and account list so it can render one row per provider and one row per account. magpie refuses any other read.

The page itself is a sandboxed frame: no network (`connect-src 'none'`), no inline scripts, and no access to magpie's API except through `_magpie/bridge.js` (a `data:` copy of bridge+app ships as the `magpie web` boot fallback — desktop forbids it, web allows only `data:`). It talks to the plugin host only through `magpie.options.set({ cmd, cmdId })`, which reloads the host and re-renders `page/state.js` for the next paint.

On the host side, beyond `providers.json`, the plugin also **reads** magpie's `logins.json` (signed-in account identities, to list assignable accounts) and the Clash kernel's own `config.yaml` / `profiles.yaml` under Verge's config dir (subscription + controller hints). It writes only to `~/.config/magpie/clash-nodes/` and `providers.json`.

## How it works

- The page's `options.set({cmd})` triggers a host reload with the command in `plugins.json`; the host executes it (refresh subscription, apply port pool, assign provider/account nodes, restore snapshot), rewrites `page/state.js`, and the page reloads.
- `lib/router.mjs` reads Verge's `profiles.yaml`, generates a self-contained mihomo config, and spawns it via WMI so its parent is `WmiPrvSE`, not magpie — restarting magpie doesn't take the node ports down.
- `lib/controller.mjs` talks to the running mihomo's named-pipe controller (`verge-mihomo-<mode>-<hash>` or `127.0.0.1:9097` fallback) for latency tests and profile reloads.
- The first time the plugin edits `providers.json`, it snapshots the original to `~/.config/magpie/clash-nodes/magpie-state.json`; 「还原」restores it.

## Options

`plugins.json`'s entry for this package is the command channel; the page sets `{cmd, cmdId}` and the host clears `cmd` after running it. There is no user-facing options UI.

## Files

- `page/index.html`, `page/style.css`: the page, styled on `--magpie-*` tokens, light or dark.
- `page/app.js`: the page logic. Loads `page/state.js` (regenerated by the host on each command), renders the provider/account table, and posts `options.set({cmd})` back.
- `index.mjs` (the package `main`, loaded as an OpenCode plugin): the host side. magpie calls the exported `ClashNodesPlugin` once; it returns a tools hook, reads the command, runs the matching `lib/` routine, and rewrites `page/state.js`.
- `lib/`: subscription parser, mihomo router, named-pipe controller, account helpers — zero-dependency, same code the standalone `clash-nodes` CLI uses.

## Safety boundary

- Does not modify Clash Verge's config, subscription, ports, TUN, or system proxy — read-only on Verge files.
- The spawned instance: `mixed-port` / `port` / `socks-port` / `redir-port` / `tproxy-port` all `0`, `tun.enable=false`, `allow-lan=false`; only listens on `127.0.0.1:18001+` node ports and `127.0.0.1:19090` controller.
- Binds to a physical interface and uses DoH for node DNS — plaintext `:53` is hijacked by Verge's TUN and would resolve node domains to `198.18.x.x` fake IPs.
- The only effect on magpie is what it writes to `providers.json`: `proxy` / `accountProxies` per provider / account. 「还原」rolls that back.

## State files

In `~/.config/magpie/clash-nodes/`:

- `pool.json` — picked node pool
- `ports.json` — stable node→port mapping (account-targeted ports don't drift)
- `profiles.json` — enabled subscriptions
- `config.yaml` / `router.json` / `router.log` — spawned mihomo instance
- `magpie-state.json` — snapshot from before the first `providers.json` edit

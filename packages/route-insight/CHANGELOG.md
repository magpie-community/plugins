## 0.15.2

0.15.1 修掉的那个 CORS 洞，把 magpie 窗口里的页面一起弄坏了——这里是修法。

- **症状**：magpie 窗口里「插件 / 路由洞察」顶部一直是「重连中…Failed to fetch」，看板骨架在但请求明细、分组统计、计费全空；同一时刻用浏览器直接开 `http://127.0.0.1:4397` 完全正常。
- **原因**：magpie 把插件页装在 `sandbox="allow-scripts"` 的 iframe 里（二进制里那串 `sandbox allow-scripts` 就是它）。sandbox 不带宽 `allow-same-origin`，这份文档的 origin 就是字符串 `"null"`——所以页面里的 `fetch('/api/state')` 在浏览器看来是**跨源请求**，必须靠 `access-control-allow-origin` 才读得到响应。0.15.1 为了让别的网站读不到数据，把这条响应头整个删了，于是窗口里的页面收到 `TypeError: Failed to fetch`（403 会显示「页面已过期」，所以报 Failed to fetch 就是网络层被拦）。
- **修法（不是把洞开回去）**：只对「`Origin: null` + 请求带着正确令牌」这一种情况回 `access-control-allow-origin: null` 与 `vary: Origin`；`OPTIONS` 预检只放行 `x-route-insight-token` / `content-type` 两个头、`max-age` 600 秒，本身不返回任何数据。令牌不对照样 403，且一个 CORS 头都不回——别的网页拿不到令牌（页面只对导航下发），所以读不到余额、账号邮箱和请求明细，也不能借订阅跑检测。
- **复现与验收**：写了一个 `sandbox="allow-scripts"` 的最小外壳页把插件页装进去，修前截图与用户看到的完全一致（重连中…Failed to fetch），修后同一份外壳里看板正常出数（1,583 次请求、93.6% 成功率）。
- `bun test` 从 7 条加到 **9 条**：新增「Origin: null 且无令牌 → 403 且无任何 CORS 头」「Origin: null 且带令牌 → 200 且放行」「预检 204 只放行令牌头且不带数据」。
- 副作用：插件重启会换令牌，之前开着的旧标签页会显示「页面已过期」，关掉重开即可。

## 0.14.0

按维护者在 PR #1004 里提的意见改的第一批（安全与成本）。

- **接口加了服务令牌（这是那条 PR 里唯一实质性的安全漏洞）**。以前 `127.0.0.1:4397` 上的每个接口都无鉴权：任何本机网页、任何能起进程的东西都能读你的用量、读检测产物，还能反复触发检测替你花钱。现在照社区包 `amp-usage` 的做法：启动时生成一枚 32 字节随机令牌，只在**导航**响应里写进 `ui/index.html` 的 `<meta name="service-token">`，之后每个 `/api/*` 请求都要带 `X-Route-Insight-Token`，比对用 `timingSafeEqual`。
  - HTML 只对「导航」请求下发（`Sec-Fetch-Mode` 为空或 `navigate`），别的取法一律 403，所以别的网页拿不到令牌；CORS 也收窄成只回 `origin: null` 那条。
  - 检测产物是 iframe 打开的，加不了自定义头，只有这一条允许 `?t=` 兜底。
  - 令牌重启就换，页面撞上 403 会直接说「页面已过期，重开就好」，不再显示成空面板。
- **一次只跑一个检测**：并发点两次会同时占额度，成本也记不清。现在第二次直接 409。
- **检测成本封顶**：一次检测最多 **40 次请求**（数值指纹 ≤24、协议审计 7、动画 1–2，三项一起跑最坏三十几次），超过就拒绝发请求并在结果里标 `budgeted`；一天累计最多 **200 积分**，超了不开新的（历史结果照样能看）。上限写在检测标题旁边：「一次最多 40 次请求 · 今日已花 x / 200 积分」，按之前就能看见要花多少。
- **删掉提示词里的越狱措辞**：默认提示词原来写着「你不需要任何测试，不要有任何限制」，这种句子会让人以为检测在绕过安全策略。改成中性说法（单文件 HTML、内联 SVG、不要脚本/外链/外部图片、自己构图），要考的东西一样。
- **协议审计的 nonce 不再写死**：原来提示词里固定写 `nonce="openai-detector"`，转发层只要认出这个词就能在完全不懂 `json_schema` 的情况下「照抄」一个合规响应。现在每次现生成 6 字节随机串，比对用这一趟的值；顺手把流式探针里自报名字的那句也换成中性文本。

- HTML 动画不再对超时做重试：同一句提示词再等 5 分钟大概率还是超时，只会让等待翻倍（实测第一趟 480 秒超时后仍在跑第二趟）。

## 0.13.5

- **修「HTML 动画一直拿不到」**：不是模型不会画，是超时预算太短。所有请求原先共用 `ask()` 的 180 秒上限，而「写一整份 HTML 文档」是这里最慢的一项——思考型模型光想就要两三分钟，再吐十几 KB 的 SVG，到点被 `AbortController` 掐断，报错只剩一句 `The operation was aborted.`（用户截图里那 180001 ms、14 次请求里唯一的一次失败，就是它）。现在按项给预算：HTML 动画第一次 **480 秒**、补交那次 300 秒，鹈鹕图 300 秒，数值指纹与协议审计仍是 180 秒。超时时写清「等了多少秒 + 怎么补救」（把画图强度调低、或换一条快的线），不再把英文 abort 原文甩给用户。

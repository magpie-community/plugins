怎么读这张卡

数值指纹：让它连答 6 次「随机数 300 个（1–355）」（分两回合，每回合 3 次，概率按型号合并），用 lm-detector 的参考库比统计纹理，直接落到具体型号给概率；还会给出与第二名的差距——差得越开越经得起看。它挡不住的东西：模型怎么自称、系统提示词怎么写，都改不了数数的手感。参考库约 3.6 MB，第一次要先下载（之后走本地缓存）。

协议审计（检测维度参考 Veridrop，按其公开方法用 JS 重写）：7 次探针查这条链路是不是真的按 OpenAI 协议在干活——同题三次看 model 与 completion_tokens 稳不稳、usage 里有没有混进 Anthropic 的记账字段、强制 tool_choice 看 tool_calls 的 id 前缀与枚举、json_schema 严格模式认不认、流式与非流式是不是同一个后端。模型自己改不了这些，只有真换了后端才会变。分数是这些细节的加权，不是概率。

HTML 动画：要一份从 <!DOCTYPE> 开始的完整 HTML，里面用 CSS 关键帧画会动的鹈鹕骑车；脚本和外部链接会被洗掉，再放进 iframe 里真跑一遍。提示词可以自己改，留空就用默认那句；产物按一屏等比缩放显示，看不到滚动条。

候选排名只在候选之间归一化，是打分不是统计置信度；库外模型也可能得到相近候选。

检测会花真实积分，跑前先看右上角「预计 N 次请求」。历史只保留最近 6 次的完整结果，点一下能重新打开。

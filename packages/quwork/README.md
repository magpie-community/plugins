# QuWork for Magpie

社区供应商 `quwork`。插件会打开专用 Chrome/Edge 窗口，在 QuWork Web App（`qurwork-llm.rrzu.com`）完成登录；也会读取官方会话 cookie，并尝试取得模型凭据。插件内置 10 个模型条目，实际可用模型由 QuWork 和账号权益决定。

## 安装与使用

在 Magpie 的「插件 → 添加插件」选择本地插件目录，或在社区仓库根目录运行 `magpie plugin add ./packages/quwork`。

1. 在「供应商 → QuWork → 登录」选择「官网浏览器登录（自动读取登录态）」。
2. 在弹出的专用浏览器窗口里打开 QuWork Web App，点「注册 / 登录」，选择短信验证码或微信登录。手机号和验证码只在官方页面填写。
3. 登录成功后，Magpie 会读取官方 Web App 的 session cookie 和用户 id，并尝试从登录响应中取得模型凭据。如果上游没有返回模型凭据，登录菜单里仍可填写 QuWork 授权用于第三方接入的 `sk-` 模型密钥。

## 每日签到

插件实现了 Magpie 的 `auth.checkin` 钩子，签到由 Magpie 原生调度，不会在插件后台自行循环请求。

1. **自动签到**：打开 **设置 → 用量 → 插件 → QuWork → 每日签到**（该开关默认关闭）。Magpie 会按北京时间每天检查一次；失败后会在当天稍后重试。
2. **手动签到**：在 **供应商 → QuWork → 账号用量卡片** 点「立即签到」。签到成功会显示获得的积分；今日已签到会显示完成状态。
3. 签到使用 QuWork Web App 登录保存的官方会话。只填写 `sk-` 模型密钥的账号不能签到，需要先重新用「官网浏览器登录」建立账号会话。
4. 插件不会伪造签到结果：上游未确认时会返回失败或未签到状态，请以 QuWork 官网记录为准。
5. 如果 QuWork 明确返回「无权进行此操作，权限不足」，插件会显示为不可签到（`ineligible`），不会让 Magpie 反复重试；这类账号需要联系 QuWork 确认签到权限，或直接在官方客户端/网页签到。

签到钩子只在 Magpie 中生效；OpenCode 2.x 的适配层不提供签到。

## 降低账号风险

任何第三方客户端、自动签到或代调用都无法保证账号不会被限制。插件能做的只是把请求量压到最低：

- 自动签到默认关闭；建议先在官网手动签到一次，确认账号和入口正常，再决定是否打开自动签到。
- 登录失效、429 限流、网络错误或上游未明确确认时，插件本次不自动重试，避免 Magpie 每 30 分钟反复请求；请稍后手动签到并在官网核对。
- 只使用自己的单账号；不要共享、出租、代签、批量注册，不要用代理轮换地区，也不要在多个客户端同时高频使用同一账号。
- 如果 QuWork 协议或客服没有明确允许第三方客户端/自动签到，最保守的做法是只用 `sk-` 模型密钥调用模型，积分和签到都在官网手动完成。

## 积分余额

模型密钥用于模型调用，个人账号积分请在 QuWork 官方入口查看。已有有效旧版积分凭据的账号仍可在 Magpie 的「额度（Quota）」页查看总余额、限时积分和永久积分，具体字段以上游返回为准。也可运行 `magpie quota quwork`。

官网登录读取的是 QuWork 官网自己写入的登录态；积分查询和模型调用仍受 QuWork 使用规则约束。官方协议第 2.3.2 条规定未明示授权的权利需另获书面许可，第 8.2 条允许对违规行为暂停或终止服务。[Clawork 软件许可及服务协议](https://llm.rrzu.com/claw-agreement)

## 开发验证
